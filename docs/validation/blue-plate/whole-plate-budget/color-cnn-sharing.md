# 补入颜色 CNN 后的三模型共享预算

2026-10-18。当前 combined gate 仍执行 `litemodel_cls_96x_r1.onnx`；HS 蓝/黄规则是额外门槛，不能替代颜色 CNN。此前检测+LPRNet 的 409.16616 / 588.55632ms 漏计该模型，只是两模型的 MAC 小计。

补齐后，同一8 DSP阵列在100MHz下，一次检测加一块/两块ROI的**纯MAC调度小计为416.13772 / 602.49944ms**。颜色模型本身为6.97156ms/ROI。51 RAM仍可作为分时共享的容量目标，但需要新增颜色图的调度与算子支持；这不是全链路延迟或整机fit结论。

## 实际模型与参考材料

直接读取冻结ONNX，SHA-256为 `fe123688d3bf08b9ef029fcd57f3ac4644ac2e5ef8b9e7a676aacd5fad152142`。现有 `model-costs.json` 只有recognizer、detector320和detector640，本次另生成 [color-model-cost.json](color-model-cost.json)，没有修改共享成本文件。

实际读取 `hyperlpr_reference.py` 的调用路径和已下载HyperLPR的 `inference/classification.py`：输入BGR、96×96、除255、CHW，不交换RGB；输出三个颜色分数，当前blue判定为argmax类别0。原调用顺序是OCR后分类。以下分时方案允许分类先执行，但预算按每个ROI均执行两者计算，不预支提前拒绝的收益。

关闭OpenCV融合后检查到52 Conv（其中17 depthwise）、35 ReLU、10 residual Add、1 AveragePool、1 Reshape、2 Gemm、1 PReLU、1 Softmax及输出Identity。卷积5,215,968 MAC，两个Gemm合计164,224 MAC，**总计5,380,192 MAC**。尾通道按8路占用计费后为697,156个MAC步骤，不能直接把总MAC除8。

本次阅读[ONNX Gemm定义](https://onnx.ai/onnx/operators/onnx__Gemm.html)与[PReLU定义及参考实现](https://onnx.ai/onnx/operators/onnx__PRelu.html)，并核对实际导出的pbtxt：Gemm为alpha=beta=1、transB=1；PReLU有一个共享学习斜率。不是把全连接或负半轴直接当作免费搬运/ReLU。已有FINN分块归约与流式权重研究继续作为共享阵列依据，见 [depthwise-schedule.md](depthwise-schedule.md) 和 [full-lprnet-sharing.md](full-lprnet-sharing.md)。本次新参考网页在线读取，未下载成源码仓库；实际模型与图导出保存在原tmp模型目录和 `tmp/blue-plate-whole-plate-budget/color-model.{dot,pbtxt}`。

## 同一阵列必须补齐的调度

| 实际层/操作 | 约束与共享方式 |
|---|---|
| 17个depthwise | 使用8个独立通道输入。36通道层尾组仅4通道有效；不能沿用检测图所有通道均整除8的假设。 |
| Conv_12 / Conv_18，C=36 | HWC紧密存储产生跨128bit字的8字节向量，分别4,900 / 1,610次。串行读两个cache字并用64bit寄存器拼接，不增加RAM；第二次读计入流量，不能声称每向量一拍。 |
| Conv_95，80→1280、3×3输出 | 整层输出11,520B。空间块S由16降为3，每块3,840B，适配4KiB写缓存。每组8路权重640B；三空间块重复载入权重共307,200B。 |
| Conv_95参数 | 1280×9B不能同时装进512×72bit参数缓存。按512/512/256通道分块，每个S块重装，累计34,560B。仍用原4 RAM。 |
| Gemm_101，1280→128 | K=1280，8路权重10,240B，装入原16KiB权重缓存；整层163,840B权重按组流入，不常驻片内。 |
| Gemm_103，128→3 | 尾组只有3个有效输出，仍占128个8路MAC步骤；三个最终logit按32bit预留。 |
| 10个residual Add | 跳连保留到最后消费者，读取两支路并对齐量化尺度；不能简单交替覆盖两个特征槽。 |
| AveragePool_99 | 1280个3×3窗口，共10,240次加法；先保留uint16窗口和，最大2295，除9可并入后续尺度但必须保留数值语义。 |
| PReLU / Softmax | 128元素PReLU需负半轴乘斜率与重量化；3类Softmax需指数、求和、归一化。当前保留算子和分数接口，不擅自删除Softmax。 |

分类阶段普通层W8/A8、池化和uint16、FC1/PReLU重量化到有符号A8、最终分数32bit均是**容量假设**。uint16池化和需零扩展后送入DSP；K=1280的无bias内积界为373,075,200，偏置及最终尺度仍需整数导出验证。归一化、残差尺度、PReLU、Softmax可分时借用现有算术单元，但尚未实现或计入时延，不能新增一套算术器后仍称8 DSP。

## 内存与每块ROI生命周期

采用静态逐节点DDR区间，所有分类特征一共647,344B，最大单张量55,296B，依赖图存活峰值110,592B。直接复用检测完成后的1,536,000B临时区，无需在线分配器；完整逐节点地址与最后消费者见 [color-cnn-sharing.json](color-cnn-sharing.json)。NMS结果表、权重和私有原始帧在该区外，不能同时覆盖。

每块ROI依次执行：从同一私有帧校正出RGB ROI并计算HS → 顺序生成96×96分类输入和94×24识别输入 → 颜色CNN → 保存3个分数与ROI编号 → 完整LPRNet → CTC及联合门槛。分类与LPRNet结束后才允许下一阶段覆盖共享特征、权重缓存和参数银行。软件原顺序也可保留，只需在进入下一网络前把输出保存到区外。

这里为固定224×64 RGB ROI预留**43,008B DDR**，为待执行的行对齐LPR输入预留**6,912B DDR**。两种resize顺序使用同一单元，分类输入放在分类临时区；暂借两个尚未存活的OCR上下文银行保存两行RGB，共1,344B，不增加片内整ROI缓存。RGB流进入分类前明确转换为BGR。原生ROI与224×64以及插值精度由主控继续验证；此处没有把304×101变成片内缓存，也没有宣布固定ROI已通过精度门槛。

| 颜色CNN新增常驻DDR项目 | 字节 |
|---|---:|
| W8原始权重（参考，不与下项重复相加） | 390,088 |
| 按8路及16B边界打包权重 | 391,040 |
| bias32/multiplier32/shift8元数据 | 48,384 |
| PReLU参数预留 | 16 |
| 每节点256B描述符 | 26,880 |
| RGB ROI与待执行LPR输入 | 49,920 |
| 在原6,498,352B上新增 | **516,240** |
| 三模型总DDR相对地址预留 | **7,014,592** |

7,014,592B小于预留8MiB，余1,374,016B；这仍是相对地址规划，未给出可直接烧录的物理地址。模型FP32文件大小和OpenCV累计blob字节不能代替量化权重容量或峰值。

片内保持原51 RAM：16权重、4参数、7输入/输出、1tag、4工作余量、15 OCR上下文、2表、1resize、1控制。颜色阶段可借用OCR上下文，OCR阶段回到9高度和+6 logits。结合保留底座及灰度缓存仍为**196/204 RAM分配目标**；上限继续固定49,248 XLR、204 RAM10、128物理DSP。尚无颜色算子、尾通道选择器、双字拼接或全链路控制的综合XLR与时序结果。

## DDR与时间口径

每ROI分类权重读取764,224B、参数读取71,424B。按物化边仅访问一次的参考流量为1,743,296B；按普通标量读取每次miss、depthwise按实际单/双字读取、输出连续写回计算，为**17,672,896B/ROI**，其中读17,053,200B、写619,696B。这是无重试的保守读拍计数，不是实测cache miss或DDR延迟上界；未含ROI搬运、resize、非线性查表及总线协议开销。

视频原有有效DDR需求497.664MB/s继续保留，新增分类流量与其他网络共享剩余服务能力。三模型MAC时间为：检测229.776ms + 每ROI（完整LPRNet179.39016ms + 分类6.97156ms）。NMS、校正、两种resize、HS、池化、残差、重量化、归一化、Softmax、CTC、DDR等待均另计；ROI数量也不能未经精度验证限定为两块。

## 验证结果

`color_cnn_sharing.py`运行通过：冻结ONNX合成全零前向得到有限1×3输出；核对实际依赖拓扑、静态区间、所有17层depthwise有效地址与跨字读取、每层权重组/输出块/参数块容量、源文件SHA前后不变。颜色图未进行整数逐元素复现或真实图像评测，不能沿用检测depthwise的通过结果来替代颜色图尾通道测试。脚本与结果哈希见 [color-cnn-validation.json](color-cnn-validation.json)。

本次完成的是把遗漏的颜色模型补齐到成本、算子和生命周期账本；量化精度、全部算子实现、综合及端到端性能仍是后续验收项。
