完整权重不必同时进入片内。对13×1层，第一段权重16,384 B，第二段10,240 B；每次只装一段。按16空间点×8输出通道保存部分和，需 **512 B**。用两个512×20 RAM提供一个32bit读写端口，每个空间点按8个字串行保存/恢复，避免要求八个部分和端口。

该层有72个输出空间点，最后空间块为8点；68输出通道的最后一组为4有效lane。上述四种组合均已检查。段间仅保存/恢复完整int32部分和，不加第二次bias、不做中间限幅或重量化。所有组跨段合计10,368次32bit部分和读写动作；只在完整K结束后输出。

其他层K≤516，无需归约分段。4个参数RAM按512×72bit有效位存bias32、multiplier32、shift8；最大256输出通道的层也能容纳，按层从DDR装载。是否需要更宽bias、乘数或移位字段仍由未来整数导出验证。

## 3. 激活与上下文存活期

原最大主干特征为230,400个元素。按A8与16B行对齐，两个 **256KiB DDR槽**足够交替保存输入/输出，实际同时存活峰值为288,000 B。每个输出块最多16空间点，最大通道256，写块正好4,096 B。整行可能大于4KiB，因此沿用检测侧块写回，不恢复成整行缓存。

13×1层若直接保存完整通道行窗需要55,296 B；本方案通过DDR和现有读cache取得卷积tap，不分配这张片内行窗。没有把行缓存费用从账本中隐去，代价是重读和cache等待。

主干tap在2、6、13、22处。生产该tap后立即池化、计算能量与高度和、投影累加，再继续主干；不同时保存四张tap，也不物化516×4×18拼接张量。

| tap | 池化输出 C×4×18 | 池化窗口 | 高度和条目 | uint16存储 | 银行数 |
|---|---:|---:|---:|---:|---:|
| 2 | 64×4×18 | 5×5 | 1,152 | 2,304 B | 3 |
| 6 | 128×4×18 | 5×5 | 2,304 | 4,608 B | 5 |
| 13 | 256×4×18 | 4×10 | 4,608 | **9,216 B** | **9** |
| 22 | 68×4×18 | 1×1 | 1,224 | 2,448 B | 3 |

最终logits为68×18×32bit=4,896 B，用六个512×20 RAM、三组32bit深度银行即可。把原C8的5高度和+10 logits银行改成 **9高度和+6 logits**，总数不变。原logits银行的20bit端口可以只用其中16bit保存高度和，需更新地址选择，不增加存储体。

三处池化的通道行为依次为保留、隔2取、隔4取，然后做3×3空间最大池化。核深度为1，所以不是相邻通道求最大值。隔2/隔4的读取不能直接套用检测depthwise“相邻8字节一次取出”的流量；已有DDR标量路径可执行，向量化必须另算。

## 4. 动态归一化与宽度条件

源模型是 `f / mean(f²)`，均值跨N/C/H/W，**没有sqrt，也没有epsilon**。硬件调度固定batch=1。遇到零能量不能悄悄加epsilon后声称与原模型一致；应由后续接口定义明确处理非有限结果。

逐支路投影使用真实数线性关系：

`logits = bias + Σ_branch W_branch · mean_H(f_branch) / mean(f_branch²)`

bias只加一次。这使每个分支可在下一主干操作前完成消费。实际预训练权重的float64验证支持重排，但不等于浮点逐位一致或定点等价。

上表uint16不是擅自把当前float高度和截断。它是**未来W8/A8部署的容量条件**：若ReLU tap以非负8bit范围表示，可以保存平均池化窗口的整数和S，暂不做除法/再量化。最大窗口40点：S≤10,200，四行高度和≤40,800，能用uint16；若DSP按有符号输入解释，必须先零扩展至17bit。已读取本机 `efx_dsp48.v` 的A19/B18端口，可承载17×8乘法，不需要第二套乘法阵列。

窗口和形式与原平均池化的比例可在分支增益中合并：设窗口点数n、分支元素数M，原f=S/n，则 `mean_H(f)/mean(f²) = n*M*sum_H(S)/(4*sum(S²))`；tap的量化scale/zero-point还需一并进入导出表达式。这里只给容量与代数关系，没有实现量化、倒数或近似。

最大分支平方和上界为 **1,917,665,280,000**，需41bit，统计可用64bit寄存器。窗口高度和乘signed INT8权重的最坏分支内积上界为 **1,326,489,600**，在int32内；经过动态增益后的跨分支logits范围仍需独立验证，不能从这个上界推出最终int32一定安全。

若必须保存原float32高度和，最大分支要18 RAM，加6 RAM logits共24，比当前15多9；不能沿用uint16账本。最少的存储调整是把宽高度和放DDR或分通道两遍读取，而不是提高预算。浮点算术本身也不能套用“一个DSP每拍一个整数MAC”的时间，本报告不声称完整FP32执行器已成立。

## 5. 共享分配与DDR

| 用途 | RAM |
|---|---:|
| 可重装权重 | 16 |
| 每层bias/scale/shift | 4 |
| 128bit数据缓存/写块 + tags | 7+1 |
| K分段部分和 | 2 |
| 原工作余量剩余 | 2 |
| 高度和 + logits | 9+6 |
| LUT/CTC目标、resize目标、控制目标 | 2+1+1 |
| **合计** | **51** |

检测/NMS、LPRNet、CTC按阶段复用，不并行占用。MAC仍为同8 DSP；重量化、归一化增益等可以安排在阵列空闲时复用乘法资源，但需要额外周期和控制，不假定另有免费的标量DSP。CTC/LUT、DMA接入及XLR仍是未关闭的缺口。

完整模型打包INT8权重源区为458,784 B，逐层元数据14,208 B，合计472,992 B。替换原检测共享布局中的16KiB C8权重预留后，包含检测工作区、NMS、原帧副本、常量/描述符及此权重源的DDR容量为 **6,498,352 B**，仍在此前8MiB相对arena内。两个256KiB LPRNet临时槽复用已释放的检测特征区，不额外相加。真实物理DDR地址仍须主控分配。

51 RAM加保留底座131及旧灰度缓存14，仍是196/204的**分配账本**；这里没有预支删除灰度缓存的收益，也没有把颜色谓词、NMS、定点算子和接口逻辑当成已综合。

## 7. 颜色交接与输入缓存

颜色候选的冻结规则是原生彩色裁剪上的OpenCV uint8 HSV：蓝 `100<H<140 && 95<S<255`，黄 `15<H<40 && 95<S<255`，严格比较蓝计数>黄计数。它是新增必要门控，不能替代识别置信度或字符完整性，也不能直接继承教师的.9/.8阈值到LPRNet。

主控正在比较原生裁剪与224×64整数Q32路径；两者插值、裁剪和颜色计数可能不同。本轮**不增加304×101缓存，不认定224×64颜色判断等价**。

如果主控验证固定224×64可用，两个计数器至少14bit，可在透视RGB流实际被消费时在线累计；黄色谓词、精确H/S边界、取消/复位与frame/candidate关联仍需实现证据。现有quad wrapper对外是灰度口，完整LPRNet需要保留内部RGB并明确转为BGR，而非复制灰度。

224×64彩色流缩到94×24，按两行RGB输入缓存是2×224×3=1,344 B，超过独立1 RAM的byte-mode容量，但可在OCR上下文尚未存活的预处理阶段暂借两个上下文银行提供2,048 B有效空间。输出直接写DDR输入槽，不必保存整张彩色ROI。这里没有选择新的插值算法；软件与硬件输入采样必须由主控验证后冻结。

本次明确了唯一K超限层的最小分块、上下文银行重分配与输入生命周期。是否采用完整预训练模型，仍取决于新的固定软件质量结果以及后续整数化、整机资源和时序验证。
