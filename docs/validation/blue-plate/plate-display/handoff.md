# 七位确认/显示接口草案

本模块独立于共享 top、DDR、分类核。主控已批准本接口方向；后续实测结果追加于本文。

## 时间与上游要求

确认域 `src_clk` 为系统 100MHz，外部提供 `now_ms[31:0]`，来自该系统域的连续毫秒计数器，每 1ms 加一，禁止用识别结果到达时间或假定帧率推算。`source_time_ms` 在采集来源帧开始事件进入此系统域时原子锁存，与 frame_id/epoch/generation 一直随帧携带。帧开始事件跨域须用可靠事件握手，时间量化误差不超过 1ms 加该事件同步延迟；不能在识别结束时补戳。

同一 now_ms 经源域寄存的 Gray 编码和目的域两级同步提供显示时钟域年龄判断；外部 now_ms 每源时钟只能保持或加一（含32位回绕）。时间计数器复位须共同复位模块并更新 epoch；独立任一域复位不允许保留另一域未完成握手。两个时钟运行后分别同步释放复位。

年龄为模32位 `now_ms-source_time_ms`，只接受差值最高位为0且小于500ms的来源。帧号前后关系同样使用半范围法；有效时间/序号间隔须小于2^31。毫秒计数回绕无需清空。显示只在下一帧开始清空已过期号码；帧中不改变文字，因此最多多显示一帧。

上游提供权威 `current_epoch/current_generation`，在 src_clk 域原子稳定。变化立即重置确认，并通过状态包发送失效；旧代次结果忽略。结果包含 version、status、来源三元组与源时间、原始720p bbox、7×7位ID、7×signed32分数、7×32位margin、task_time_ms；本模块只检查状态及ID合法性，分数完整保留，不重做分类门限。ready/valid 反压时整包须保持。

## 确认与显示策略

同代次、严格更新的来源 frame_id、非倒退源时间、未过期、状态成功、七位合法才参与确认。连续是连续处理的有效结果，不强制 frame_id 差值为1（识别允许跳过未接收帧）；中间拒识、无目标、总线/超时错误、号码变化、bbox目标跳变或支持源时间间隔达到500ms均重置。重复和乱序来源只忽略，不能累计、不能更新时间或延寿。每个已接收识别任务必须报告成功或失败，不能静默丢掉拒识事件。

同目标初始规则：bbox IoU≥1/2，且横纵中心移动均不超过前后较小尺寸的1/4；坐标必须落在1280×720内。采用整数交叉乘法，避免除法。连续三次相同七位才显示；新号码/新目标从1开始，旧确认立即失效。无新结果时按最后支持源帧年龄自动清空。

采用同类 bundled-data 两相握手的显式 ready/valid CDC，held 包在目的域接收确认前不变；确认输出可反压，控制失效与年龄过期优先。显示域保存 pending 包，在 `frame_start`（必须处于消隐）原子提交 active 的七位、状态、valid及元数据。显示域在提交时重新检查源年龄，阻止 CDC 堵塞后的旧确认重新点亮。

配置用独立64位整包握手通道传播，不受结果通道 `display_accept` 反压影响。连续运行的两时钟下，配置变化稳定后最多16个源时钟周期+16个显示时钟周期即可在目的域获知（保守上界）；随后第一帧开始清空。时钟停止时不承诺墙钟传播上界，恢复后按同一周期界限处理；停止扫描期间也没有新显示帧。配置代次不得快速回退形成ABA。

目的域观察到无效包或配置变化时，如果已有 active/pending 有效号码，就置位粘滞 clear_pending；成功包可以更新 pending，但不能抹掉清除事件。下一帧先显示未识别，再下一帧才允许新的已确认号码。旧代次包即使清除之后到达，也被独立配置标签检查拒绝，不会重新点亮。

frame_start 与结果握手同拍时，新收到整包优先于旧 pending，失效/配置清除优先于成功显示；包仍保存在 pending，下一帧可再次审查。所有 active 字段只在 frame_start 更新；invalid时七个active ID全部置127，元数据保留用于诊断。到期pending有效位也清除，避免长期停流后时基回绕使旧号码复活。

固定号码栏显示32×32像素省份汉字及六位，未确认显示“未识别”。字体从可再分发开放字体生成，ID顺序读取冻结 model.py 的 CLASSES。像素、DE/HS/VS 等延迟统一，不画跟踪框，不加菜单或记录。

## 最终独立交付

入口为 `tools/blue_plate/plate_display/plate_display.v`，组合 `plate_confirm.v`、`plate_mailbox.v`、`plate_display_state.v`、`plate_osd.v`。源码目录 README 含复现命令。没有接入共享top/DDR，没有修改char_model/candidate/char_linear，没有覆盖release或操作硬件。

结果输入宽715位，输出active包宽716位，最高位715为确认有效。其余位段由 `generate_assets.py` 单源生成到 `plate_defs.vh` 与 `assets.json`；七位ID低位先放第0位省份。版本为1，状态0成功、1无目标、2拒识、3上游错误；4过期、5配置变化、6非法输入由本模块产生。任何非零上游状态都重置连续确认。bbox为原始720p轴对齐 `x,y,width,height`，右/下端采用排他坐标；输入必须满足非零尺寸及边界检查。

`result_valid/result_ready` 是src_clk域整包握手。`frame_start/display_accept`及x/y、RGB、DE/HS/VS属于pixel_clk域。`display_accept`正常接1。active元数据与7组分数/margin保留，invalid时仅清确认位及七个ID；不把整数分数当概率。RGB及全部视频控制信号延迟一拍。默认栏位(16,656)、256×48，适用于1280×720。

### 已通过的验证

- 三组时钟周期10/6ns、10/14ns、10/22ns各64项状态检查，共192项。覆盖重复/乱序、号码切换、连续框移动和框跳变、拒识/无目标/错误/非法ID/越界框/版本错误、499/500ms、未来/倒退源时戳、32位时间与帧号回绕、反压、时钟停止恢复、共同异步复位及错相同步释放、帧中到达和同拍frame_start。
- 连续39次generation改变及中途epoch改变时，结果通道保持反压；最终配置分别86/122/208ns被目的域观察，低于256/384/512ns的保守上界。clear_pending在无效包后跟随三个成功包时仍保证一帧未识别，下一帧才显示新确认。
- 合法七位布局覆盖全部65类字形，另含未识别与空格。819,200个RTL输出像素与独立Python ROM位图参考逐点一致，包含栏外原图保持和RGB/DE/HS/VS对齐。
- [最终仿真记录](verification.json)、[字体完整预览](font-atlas.png)、[号码栏预览](osd-preview.png)、[源码/综合冻结清单](final-evidence.json)。这些都是合成结果输入的协议与显示证据，不是实拍识别准确率证据。IoU/位移门槛仅验证了整数实现和合成运动样本，尚未实拍定型。

主控另独立复跑64项状态检查，并把字形首位扫描扩展到65 IDs+未识别，1,689,600像素零差异，见[独立复核](independent-review.json)。其后最终OSD把两处表达式位宽写显式，本地OSD测试改为合法七位布局覆盖65类；最终版本已重跑上面的192项/819,200像素。状态RTL与主控审核版完全相同，两个文本差异文件及SHA均记录在冻结清单，不把主控旧快照当最终源码哈希。

### 最终独立 map

Efinity 2026.1.132.4.5、Ti60F225/I3、retiming=0，两个独立工程均map通过：

| 模块 | RAM10 | DSP48 | LUT4 | FF | ADD |
|---|---:|---:|---:|---:|---:|
| OSD单独 | 16 | 0 | 475 | 34 | 7 |
| 完整确认/CDC/OSD | 16 | 3 | 2740 | 4085 | 400 |

16个RAM10均由font映射而来，实际Memory Mapping Report已逐实例核对。因此同always块的异步复位没有导致字库展开为逻辑。原始报告：[OSD](plate_osd.map.rpt)、[完整模块](plate_display.map.rpt)。初版字符槽索引乘7被工具映射为1个DSP12，已改为等价6位移位减法，最终OSD无DSP；像素对照已重跑。

完整独立顶层有866输入位/746输出位，包含诊断包，未给这些测试端口分配物理管脚。资源是独立map估算，不把LUT与FF相加当最终XLR，也不声称100MHz/74.25MHz时序闭合。实际集成须遵循 [CDC约束交接](cdc-constraints.md)，并在整机内部连线后做PNR与时序报告。

综合保留只读font无动态driver提示，初始化及16个RAM映射均存在；单独OSD不使用active包中的分数/来源字段，因此相应输入被优化并报告未连接。这些不是已执行的CDC/PNR检查。
