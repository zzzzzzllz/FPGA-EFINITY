# 30fps Canny / 20ms 曝光

当前板上保持产品版 `0x6010100f`，完整 2560×1440 采集、左灰度右 Canny、实时模式。Canny 阈值 24/12，中值及识别关闭；RGB 增益 389/256/427，gamma 0、BGGR。

传感器实时读回：曝光 1800 半行，HTS 1400、VTS 1500；模拟增益寄存器 80/3f（约 3.032 倍），数字增益 00/80（1 倍）。按实测帧率折算曝光约 20.003ms。

用户实屏反馈由主控窗口转述：“亮度合适，忽明忽暗减轻”。曝光和亮度已接受；静止 Canny 边缘闪动仍未验收解决。

## 加载和恢复

- `load-30fps-20ms.cmd`：先调用冻结产品的 `quality_preserve/board/load.cmd`，成功后应用 `target-sensor.json`。两步均检查退出码。只加载 SRAM，不写 Flash；断电后需要重新运行。
- `restore-30fps-before-exposure.cmd`：仅在当前 30fps 产品版上恢复本次曝光调整前的传感器配置（2989 半行、约 2.021 倍增益）。这是手动恢复入口，本次未执行。
- `previous66/`：切换前 60fps 版本的位流、控制程序、profile 及构建验证副本。其哈希见 `preflight.json`；未恢复到该版。

组合加载入口已检查相对路径和错误处理；底层产品加载、曝光写入及实时读回分别实测通过，未为验证组合入口追加一次重载。

## 验证

`target-health.jsonl` 保存 17 次状态读数，覆盖 31.672 秒。采集及处理均为 29.99495fps，显示约 59.95832fps。采集错误、MIPI 标志、显示欠载、Sobel 过载、混帧、失败帧、总线错误、结果溢出和跳帧均为零增量。启动阶段累计欠载为 198，检查窗口内未增加。

`verification.json` 保存首尾读数、参数、帧率和各项检查结果。产品位流、201 项构建输入及本次使用的原控制源码哈希复核一致。没有修改冻结产品工程和 board 历史证据。

本次未新增 ROI 图像采样，未测量 LED 实际闪烁频率。历史 A/B/A 对照显示，此曝光/增益组合把区域均值峰峰波动从约 1.9～2.0 DN 降至 0.175 DN，但局部边缘变化未改善（见上级 `findings.md`）。因此不能据此宣布边缘稳定性目标完成。下一步由主控结合现有噪声和 NMS 切换证据判断后续方案。
