# 赛题四：实时图像边缘检测系统要求解读

我们选择的是《全国大学生嵌入式芯片与系统设计竞赛'2026 FPGA 创新设计赛道选题指南（易灵思）》中的**赛题四：基于 FPGA 的实时图像边缘检测系统**。

原始文件：[易灵思赛题 PDF](../reference/hardware/易灵思.pdf)。平台说明见第 3—4 页，赛题四见第 12—17 页。项目内这份 PDF 与本次提供的文件 SHA-256 一致。

这道题要求做出一套能实际运行的设备：摄像头拍摄画面，FPGA 实时完成灰度化和边缘检测，显示器同时展示灰度画面与边缘结果。灰度化只是其中一步，完整目标是“采集 → 处理 → 显示”。

下面按 1—13 逐项解释。条目中的“检查方法”是把要求转成便于验收的动作，不是赛题另行规定的评分细则。

## 1. 使用易灵思 FPGA 搭建完整系统【平台与总体任务】

**出处：第 3—4、12 页。**

- 平台章节列出基于 Ti60F225I3 的 Ti60F225 开发板，推荐 SC431HAI 摄像头；VF-Ti60F225 开发板也可用于赛题四和自由选题。
- 摄像头通过 DVP 或 MIPI 接口接入，图像算法在 FPGA 内实现。
- 总体任务描述支持 HDMI/VGA 显示；基础要求第 4 项明确写的是 HDMI 显示驱动。我们现有 HDMI 路线直接对应这一要求。

**要做什么：**把摄像头、FPGA 和显示器连成可实时演示的系统，让 FPGA 真正完成图像处理。赛题四没有单独要求必须使用 RISC-V、神经网络或 AI 模型。

## 2. 稳定采集摄像头图像【基础要求 1】

**出处：第 12—13 页。**

- 采集分辨率至少为 **640×480**。
- 采集的数据进入 FIFO 或 Block RAM 行缓存，供后续处理使用。
- 采集稳定，无丢帧、无错位。

**要做什么：**让摄像头正常输出视频，FPGA 正确接收每个像素以及行、帧边界。只有彩条显示正常，还不能证明摄像头采集正常。

**检查方法：**先显示摄像头原画，移动拍摄物体，检查画面是否持续更新，有无错行、偏移、花屏；结合帧计数或调试记录检查丢帧情况。赛题四这里未规定摄像头采集帧率的具体最低数值。

## 3. 将彩色图像转换成灰度图【基础要求 2】

**出处：第 13 页。**

- 在 FPGA 内完成彩色转灰度，作为边缘检测的输入。
- 使用 FPGA DSP 块或移位加法完成乘法运算，避免使用除法器。

**要做什么：**把彩色画面转换为只保留明暗信息的灰度画面，让后续算法根据亮度变化寻找边缘。

**检查方法：**显示出的灰度画面应保留场景结构和明暗层次，并与摄像头画面对应。赛题没有在这一项指定唯一的灰度转换系数。

## 4. 实现 3×3 Sobel 边缘检测【基础要求 3】

**出处：第 13、15 页。**

每次取相邻的 3×3 像素窗口，按以下卷积核计算水平、垂直梯度：

```text
Gx 核：             Gy 核：
-1   0  +1          -1  -2  -1
-2   0  +2           0   0   0
-1   0  +1          +1  +2  +1

梯度幅值近似：G = |Gx| + |Gy|
```

- 用绝对值相加近似梯度幅值，避免开方。
- 将梯度幅值与阈值比较，输出二值化边缘图像。
- 阈值可参数化配置。
- 设计两个行缓存，保存前两行；加上当前行，形成滑动的 3×3 窗口。每个行缓存的深度对应图像宽度。

**要做什么：**把物体亮暗变化明显的位置提取出来，形成黑白轮廓图。Sobel 是基础要求，做了 Canny 升级后仍应保留并验证 Sobel 功能。

**检查方法：**对准棋盘格、数字纸或几何图形，观察轮廓是否对应真实物体，是否发生整体偏移、断行；仿真检查窗口和梯度计算。基础要求中的“阈值可参数化”与第 9 项的“现场按键实时调节”属于不同层次。

## 5. 稳定输出并对比显示【基础要求 4】

**出处：第 13 页。**

- 生成标准 HDMI 显示时序，最低要求为 **640×480@60Hz**。
- 可采用左右分屏：左侧灰度图，右侧边缘图。
- 也可采用上下分屏：上半部分灰度图，下半部分边缘图。
- 或采用画中画叠加显示。
- 显示稳定，无闪烁、无撕裂。

**要做什么：**让观众直接对照同一场景处理前后的效果。基础分屏条目指定的是“原始灰度图像”与“边缘检测结果”。

**检查方法：**移动物体，观察两路图像是否对应、边缘位置是否正确，以及画面有无闪屏或上下内容断裂。只证明输出分辨率达到 720p，还不足以证明帧率、显示稳定性和对比功能都达标。

这里的 60Hz 是显示输出刷新要求，不能直接当成摄像头每秒采集 60 张不同图像，也不能据此声称算法每秒处理了 60 张新图像。

## 6. 提交源码、约束和演示视频【基础要求 5】

**出处：第 13 页。**

赛题四明确列出的基础提交材料是：

- 完整 RTL 源码，使用 Verilog 或 VHDL。
- 约束文件。
- 实物演示视频，展示摄像头采集和边缘检测效果。

**要做什么：**保留可用于复现设计的源码与约束，并录制实际运行画面。演示对象可选黑白棋盘格、印有数字的纸张、人脸轮廓等，原文是举例，没有要求每一种都必须拍摄。

**检查方法：**确认提交材料对应演示版本，视频中能看清拍摄对象、原始灰度图和边缘结果。本 PDF 的赛题四章节未列出评分占比、提交截止日期或完整报名材料清单。

## 7. 采用流水线实时处理【总体架构要求】

**出处：第 12、15—16 页。**

```text
摄像头 → 灰度化 →〔中值滤波，高阶功能〕→ Sobel → 对比/叠加显示
```

- 各模块分级处理像素，模块之间用寄存器传递数据。
- 利用行缓存形成局部窗口，使采集、计算和显示能够并行进行。
- 流水线填充后，在持续有效输入条件下支持每时钟输出一个处理结果。

**要做什么：**持续接收视频、持续输出结果，体现 FPGA 的并行处理能力。

原文用“零延迟”形容实时效果。工程上仍有行缓存等待和流水线寄存器延迟；使用 DDR 帧缓存时还会增加帧相关延迟。验收应记录实际延迟与吞吐率，不能把这个宣传性表述当成物理延迟必须为零。

原文提到的四级 Sobel 流水线、最高 220MHz 和中值网络 5 个时钟周期属于技术说明或示例，不是基础要求中统一规定的最低指标。

## 8. 加入 3×3 中值滤波【高阶挑战 1】

**出处：第 14—15 页。**

- 位置在灰度化之后、边缘检测之前。
- 对 3×3 窗口的 9 个像素排序，取中间值作为输出。
- 合理设计排序网络，可采用并行比较网络，避免串行排序影响吞吐率。
- 目标是抑制椒盐噪声，减少噪点造成的假边缘。

**要做什么：**先清理灰度图中的孤立噪点，再检测边缘。

**检查方法：**在同一带噪画面下比较开启和关闭滤波的效果，检查噪点是否减少、物体轮廓是否保留。任务说明中提到了中值滤波，但正式分项把它列在高阶挑战；本文沿用这一分组。

## 9. 用按键或拨码开关实时调整阈值【高阶挑战 2】

**出处：第 14、17 页。**

- 通过板载按键或拨码开关实时调整 Sobel 阈值。
- 提高阈值时，边缘减少；降低阈值时，边缘增多。
- 设计按键消抖模块和阈值寄存器。

**要做什么：**现场操作板子就能调节边缘检测灵敏度，并立即看到变化。

**检查方法：**对同一场景连续增减阈值，确认效果方向正确，按键不会因抖动误触发。只通过电脑串口调参，不直接对应本条指定的板载按键或拨码交互。

## 10. 使用外部 DDR 保存整帧图像【高阶挑战 3】

**出处：第 14 页。**

- 将完整一帧图像写入外部 DDR，分离采集、存储、读取和处理。
- 调用 Efinity 中的 DDR 硬核控制器 IP。
- 在此基础上可实现回放、帧冻结、多帧对比等功能。

**要做什么：**让系统能够保存完整画面并按需读取。行缓存只保存局部图像行，与这里的整帧存储不同。

**检查方法：**验证完整帧的 DDR 写入和读取，再演示实际选做的冻结、回放或多帧对比功能。原文将这些功能列为可实现的例子，没有写成三项全部必做。

## 11. 升级为 Canny 边缘检测【高阶挑战 4】

**出处：第 14 页。**

原文给出的算法步骤为：

```text
高斯滤波 → 梯度幅值和方向计算 → 非极大值抑制 → 双阈值分类 → 滞后边缘连接
```

**要做什么：**通过完整处理流程获得更细、更连续的边缘；仅加入第二个阈值，并不等于完成了 Canny。

**检查方法：**对照上述阶段检查实现，再用同一场景与 Sobel 比较边缘宽度、连续性和噪声情况，同时验证实时处理能力。如果做了硬件近似，应说明与上述流程的对应关系及实际效果。

## 12. 将彩色边缘叠加到原始彩色画面【高阶挑战 5】

**出处：第 14 页。**

- 保留原始彩色图像。
- 将边缘用红色等明显颜色绘制到原图上。
- 处理 RGB 三通道的叠加逻辑。

**要做什么：**显示彩色实景，并给物体轮廓描上彩色边线。

**检查方法：**移动物体，检查彩色边线能否贴合物体轮廓、有无错位。该项强调原始彩色画面上的彩色边缘，与第 5 项基础灰度对比显示不同。

## 13. 在边缘图上识别简单形状【高阶挑战 6】

**出处：第 14—15 页。**

- 在边缘检测结果上识别特定形状，例如圆形、矩形。
- 可以采用轮廓检测和几何特征匹配。
- 在屏幕显示识别结果，例如“检测到圆形”。

**要做什么：**让系统进一步判断轮廓是什么形状，并给观众明确的识别结果。这一项没有规定必须使用神经网络。

**检查方法：**分别拍摄圆形和矩形，检查识别文字是否正确、能否随目标变化更新。画出轮廓但没有分类结果，不能证明已完成这一项。

## 要求与验收清单

下面的方框用于后续验收记录，当前均未勾选；它们不表示代码尚未实现，也不表示功能已经通过。

- [ ] 平台和接口符合赛题四，核心图像处理在 FPGA 内完成。
- [ ] 采集达到 640×480 或以上，稳定、无丢帧、无错位。
- [ ] FPGA 内完成灰度转换，使用 DSP 或移位加法，避免除法器。
- [ ] 两行缓存和 3×3 窗口工作正确，完成 Sobel、幅值近似和参数化阈值比较。
- [ ] HDMI 至少达到 640×480@60Hz，完成灰度/边缘分屏或画中画叠加，显示稳定。
- [ ] 连续视频流水线正常工作，实际处理帧率与延迟有验证依据。
- [ ] RTL 源码、约束和对应版本的实物演示视频齐全。
- [ ] 高阶：中值滤波能抑制噪点并保留主要边缘。
- [ ] 高阶：板载按键或拨码能实时调节 Sobel 阈值。
- [ ] 高阶：DDR 整帧读写正确，所选帧功能可演示。
- [ ] 高阶：Canny 各处理阶段与效果已验证。
- [ ] 高阶：彩色边缘与原始彩色画面正确叠加。
- [ ] 高阶：简单形状识别正确，并在屏幕显示结果。
