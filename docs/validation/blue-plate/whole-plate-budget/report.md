## 3. 当前 LPRNet 的准确成本与语义

以 batch=1、BGR 94×24 为输入，逐层实际 hook 和独立尺寸公式检查结果见 [layers.csv](layers.csv)、[costs.json](costs.json)：

| 项目 | 数值 |
|---|---:|
| 卷积 MAC / ROI | **144,411,264** |
| 可训练参数 | 446,976 |
| 卷积权重 / 偏置数 | 443,344 / 1,576 |
| INT8 权重 + INT32 偏置 | 449,648 B |
| 再含逐输出通道 INT32 乘数、移位 | **462,256 B** |
| 最大输出特征图 | 230,400 个元素 |
| 最终 logits | 68×18 |

权重和大特征图都必须放 DDR。剩余 73 RAM 的理想位容量是 93,440 B，常用 1024×8 模式仅 73 KiB；最大 INT8 输出就要 225 个这种 RAM。原浮点输入归一化是 `(pixel−127.5)/128`，整数部署须通过校准/QAT确定缩放与零点，不声称与简单 `pixel−128` 完全相同。

### 通道池化、BN 与动态归一化

源码对四维输入使用 `MaxPool3d(kernel=(1,3,3))`。实际行为已用张量逐元素验证：

- 第一层空间池化保留所有 64 通道。
- 第二层 stride=(2,1,2) **抽取 128 通道中的 0,2,…,126**，再做空间最大池化。
- 第三层 stride=(4,1,2) **抽取 256 通道中的 0,4,…,252**，再做空间最大池化。

这里不是通道平均，也不是在相邻通道中取最大值。硬件必须保留这一语义。

推理态 BatchNorm 可折入相邻卷积权重/偏置。但四个 context 分支执行的是 **`f / mean(f²)`，不是 RMS，也没有 epsilon**；均值包含 N、C、H、W 全部维度。分支大小分别是 4,608、9,216、18,432、4,896 元素，拼接后 37,152 元素。batch>1 会让不同车牌共用分母；当前硬件契约固定 batch=1。

每个分支需要先完整求平方和，再归一化读取，不能折成静态 BN。最小实现把池化后的分支写 DDR，同时累计平方和，完成后计算四个倒数，再重读送入最后 1×1 卷积。最大分支 INT8 平方和上界 301,989,888，29 位无符号可装下；更宽中间量应使用至少按量化范围推导的累加宽度，统计通路可用 64 位。分母为零应返回明确无效结果；添加 epsilon 或改成 RMS 是模型变更，须验证识别效果。

现有 68 类含 I、O、blank，显示系统是 65 类。CTC 先合并重复并去 blank，再映射字符编号；I/O 或非法长度应拒绝。不能截取或补齐字符来强制形成七位结果。

### 行缓存与空间池化

完整通道行缓存不是总能装下：尾部 13×1 卷积需要 12×18×256=55,296 B，即 54 个 byte-mode RAM；与 32 路权重双缓冲的 26 RAM 相加已超出剩余 73。按 32 输入通道分块则为 6,912 B，约 7 RAM，但要付出 DDR 重读和部分和保存。

空间最大池化所需选中通道两行缓存最大 11,776 B；128 通道的 5×5 context 平均池化若保留四行则要 46,080 B。采用串行调度、DDR 特征图与可复用 tile 缓存，不同时常驻所有层行缓存。context 不必整张留片内。

## 4. 单一复用引擎的资源草案

数据排布采用 HWC/通道块连续布局；权重预打包为输出组、K tile、K、PE。每拍一个输入值广播到 P 个不同输出通道权重，累加到 P 个累加器。空间 tile S=16，归约 tile K=512。每个 K tile 前后按 32 位字串行搬运部分和，避免为 P 个同时读写的部分和堆砌宽 RAM。最后串行逐输出重量化。

| RAM 用途 | P=16 | P=32 | 组织方式 |
|---|---:|---:|---|
| 权重双缓冲 | 14 | 26 | 每份 512×(P×8)，按 20 位宽分银行 |
| 部分和 | 2 | 2 | S×P 个 int32，串行端口 |
| 激活缓存 | 8 | 8 | 8×1024×8；128 位输入拍可分两周期写入 |
| AXI128 读、写突发缓冲 | 14 | 14 | 每方向 7 个宽度银行 |
| 偏置、乘数、移位 | 4 | 4 | 最大 768×32 位 |
| 68×18 int32 logits | 6 | 6 | 512×32 深度级联 |
| **合计 RAM** | **48** | **60** | 留给其他新增部分 25 / 13 |
| MAC DSP + 重量化 DSP 预留 | **16+4=20** | **32+4=36** | 留给其他新增部分 19 / 3 |

这是组织方式与容量估算，尚未综合。四个额外 DSP 是一个 32×32 乘法通路的预算预留，具体综合可能不同；统计可在卷积空闲时复用 MAC。若重量化也串行复用 MAC，可减 DSP，但需重算周期。已有 frame_reader 的 7 RAM 是专用视频读取缓冲，不能当作任意张量 DMA 免费复用。该草案未包含定位器和新增接入逻辑，尤其**未证明 XLR 能落入剩余约 6k 的理想空间**。

## 5. 计算量、DDR 流量与延迟条件

假设 100 MHz、INT8 激活/权重、BN/ReLU 融合、DDR 中间特征图、输出通道尾部补齐到 PE 宽度。统计包含 68 通道补齐造成的空运算。K tile 的部分和装入和写回都计入，因此比纯 MAC 峰值更接近可实现调度。

| 每 ROI | P=16 | P=32 |
|---|---:|---:|
| 纯有效 MAC 理想时间 | 90.257 ms | 45.129 ms |
| MAC 调度周期，含尾部 | 9,233,280 | 4,755,024 |
| 串行部分和周期 | 2,735,872 | 2,756,608 |
| 串行输出重量化周期 | 1,325,888 | 1,325,888 |
| **以上算术调度时间** | **132.950 ms** | **88.375 ms** |
| 激活读取有效字节 | 9,233,280 | 4,755,024 |
| 权重读取有效字节 | 9,445,248 | 9,752,768 |
| 输出及其余算子有效字节 | 2,432,352 | 2,432,352 |
| **分块方案有效流量** | **21,110,880 B** | **16,940,144 B** |
| 每个非权重字节都独占 16 B 拍的悲观数据拍流量 | 196,095,360 B | 124,750,784 B |

分块方案权重在 16 个空间点内复用，整模型会多次读取权重。悲观数据拍情景只说明缓存与布局失效的代价，不含命令、刷新、仲裁和重试，也不是实际总线效率预测。激活广播并不意味着每拍都向 DDR 发一个字节请求，必须用连续突发和缓存提供数据。

其他比较口径：仅权重/量化元数据、输入和最终 logits 的冷启动必要流量为 473,920 B；各算子各读一次输入、写一次输出的理想 spill 参考值为 3,860,416 B。二者都不能代替有限 RAM 下上述分块方案的实际流量。

还需计入约 **1,499,136 次最大值比较、1,050,624 次平均池化加法**，以及 37,152 次平方、37,148 次归约加法、37,152 次归一化乘法、四次倒数和 CTC。若比较/加法各按一拍串行执行，仅前两项就约 25.50 ms；因此 **88.375 ms 不是整牌推理时间**。

视频底座持续有效流量约 497.664 MB/s（原图写/读各 82.944，结果写 110.592，HDMI 读 221.184）。P=32 每秒识别 10/20 个 ROI 另需约 169.401/338.803 MB/s 有效流量，尚未包含定位和校正。128 位×100 MHz 的 1.6 GB/s 是接口名义速率，不是已证明可用 DDR 带宽。

若仲裁能保证 CNN 剩余有效带宽 B，则数据时间是 D/B：P=32 在 200/500 MB/s 时为 84.701/33.880 ms。理想重叠下取 max(算术时间,D/B)，完全串行时相加，再加非卷积和接入开销。**没有可保证的带宽或等待上限，就不存在有限的整链路最坏延迟保证。** 本次未改变仲裁器或据此承诺帧率。

## 6. 修正 HyperLPR 的硬件下界

读取主控 `tmp/blue-plate-normal-g1/mature-detector/model-costs.json` 和 `resource-audit.json`，只纠正资源/算力口径，不重复准确率实验：

|---|---:|---:|---:|---:|
| recognizer | 319,933,440 | 2,233,656 B | **82.034 ms** | 99.979 ms |
| detector320 | 183,417,600 | 457,212 B | **47.030 ms** | 57.318 ms |
| detector640 | 733,670,400 | 457,212 B | **188.121 ms** | 229.272 ms |

均按 100 MHz、每 DSP 每拍一个 MAC、无停顿。先前 43 DSP 漏计透视的 1 DSP 与完整显示的 3 DSP，应改为 **39 DSP**。detector320+一块/两块识别的纯 MAC 理想时间已经是 **129.064/211.099 ms**，尚未包含 DDR 和其他算子。

recognizer 的 MAC 包含 4,899,840 次 MatMul；图中还有 LayerNorm、Reduce/Sqrt、Softmax、Sigmoid、残差与布局变换。不能用 LPRNet 卷积算子的实现成本覆盖这些操作。共享同一阵列可以作为后续研究方向，但本次不增加第二个执行器。

DSP 双乘法的纸面峰值可使表中时间减半，但 24 位累加不能直接覆盖 K=3328 的最坏 int8 归约；输入零点还可能使中心化激活扩到 9 位。必须分段累加、保留 int32 部分和并验证符号与 DSP 映射，本次不计入已获得吞吐。

## 7. 接入契约与下一步门槛

1. **输入与帧寿命。** 沿用 frame/ROI/job ID 和原帧 hold/release。输入完全落入独立 DDR 张量区后才释放所需原帧。现有透视 wrapper 对外是灰度写口，内部 fetch 才有 RGB；需接出 RGB、明确 RGB→BGR、尺寸与归一化。原版模型需要彩色输入，不能直接喂灰度。当前 224×64 校正再 resize 与直接校正到 94×24 的插值不同，后者须先验证识别影响。
2. **DDR 与执行描述。** 模型权重、量化参数、输入、双 feature 区、context 区和 logits 区显式分配，不能覆盖视频帧槽。描述符包含地址、C/H/W、stride、padding、K tile、量化参数、模型哈希、job/frame ID。权重和描述符在执行期间保持不变。张量 DMA 是新增接口，不能无条件套用专用视频行读取协议。
3. **仲裁与失败。** 保留显示/视频必要带宽；CNN 使用 ready/valid 背压。超时、取消后须排空已发事务再归还 buffer，禁止把旧任务结果发布到新帧。结果含 success/reject/error、字符数、映射后编号、可信度和 frame/job ID；低质量拒绝与 DMA 错误分开。logits 不是现有显示置信度，需要定义可校准评分。
4. **先验证模型效果。** 主控维护训练/验证/冻结评测边界；比较整牌准确、错误接受、拒绝、校正依赖和量化前后变化。此次未运行评测图像，也不使用既有 388 张结果反复调参与宣称独立泛化。当前公开 LPRNet 的原结果并未超过旧方案；更高质量的 HyperLPR 说明整牌路线值得研究，不等于其模型已适配 Ti60。
5. **再验证真实成本。** 候选整数模型通过效果门槛后，先 map 一个复用引擎、DMA和必需算子，检查原定 49,248/204/128 预算；XLR 确认后再做整链路集成、PNR和共享 DDR 压力验证。禁止用器件物理上限替换原预算。

维持当前空间形状、只按比例缩窄隐藏通道的解析草案：

| 隐藏宽度 | MAC / ROI | INT8 权重+INT32 偏置 |
|---|---:|---:|
| 1 | 144,411,264 | 449,648 B |
| 1/2 | 41,848,704 | 182,352 B |
| 1/4 | 13,459,968 | 82,496 B |

这不是已训练模型，也不等于论文 reduced 版。可先把 **15–25M MAC/ROI** 当作轻量模型研究区间：现有全帧读取约 38.72 ms、校正每 ROI 约 9.93 ms；两候选顺序处理时，这些固定成本已明显占用时间。以 16 PE、60% 有效 MAC 利用率估算，15–25M 还需每 ROI 15.63–26.04 ms，且另有非卷积开销，不能据此承诺 10 Hz。降低通道数后的真实识别、整数归一化和 XLR 都是进入 RTL 前的必要证据。

## 8. 验证与复现
