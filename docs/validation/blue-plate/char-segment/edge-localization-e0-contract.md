# E0：两处梯度、固定参数的开发集定位实验

本合同替代前一份研究计划中的“固定阈值与全帧 Otsu 比较”。旧冻结文件保留。此次固定为 A：中值旁路、3×3 Gaussian 后的主 Sobel Gx；B：中值前原始 Gx。各处理既有304帧一次，共608次传统定位；不运行检测、颜色分类或 OCR 模型，不读取84/112图片，不改变产品。

## 入口与执行条件

使用 `tools/blue_plate/edge_reference/reference.py` 的 DDR 整数灰度口径，固定配置 `0x6038`、`recognition=False`。本窗口的精简 A/B 计算必须先与该窗口通过 RTL 对照的参考逐像素一致。其 `report.json` 必须为 PASS，参考源码哈希必须匹配；本窗口再用4个合成尺寸（含1280×720）核对所有 Gx 字节。准备阶段不打开源图。

A 代表固定滤波配置的比较入口。实际展示页的主 Sobel 前处理会变化，另发固定配置作业要计入 DDR 读取及处理时间。B 原始梯度不随中值、高斯设置变化。此次软件耗时不代表 FPGA 吞吐，梯度参考通过也不代表定位实现已通过 RTL。

## 固定处理规则

- 源图只读取一次，先核对冻结 SHA，再采用既有 `INTER_AREA` 等比缩放、居中黑边的1280×720画布。
- 两入口均用 `abs(Gx)>56`，最外一行一列清零；17×3闭运算，补零边界。不加入全帧自适应阈值或参数扫描。
- 8连通行游程合并：每行128段、256活动标签、32几何候选。每行先统一等价引用，再回收别名和已结束组件；候选存储达到32后，第33个使整帧失效。行或标签溢出立即停止该帧的有限容量模拟。输出诊断日志不计作额外硬件存储。
- 组件几何范围：宽80…640、高20…160、宽高比2.3…6；左右各外扩 `ceil(0.04w)`、上下各 `ceil(0.20h)`。候选须距画布边界至少1像素。
- 从原彩色画布按既有整数 Q32/Q5 路径采样224×64。正、反灰度极性分别复用既有 `projection-char` 七区结构；保留局部32-bin Otsu、谷值及 rim 规则。文字行斜率绝对值≤7/80，高度比≥65/100，中心残差≤3/10最大高度。ROI结构用的 Otsu 与被取消的全帧梯度 Otsu 对照是不同步骤。
- 每个候选记录两极性证据。容量溢出或越界时明确记录结构跳过原因。恰好一个候选通过才选中，多个记 ambiguity 并拒绝；同一框的两个极性只计一个候选。GT和OCR均不参与挑选。

这一步输出轴对齐框，不做额外旋转、剪切或透视边界估计。七区结构通过不证明是真实可读字符；合成七根竖条通过是已记录的反例。

## 身份与评价

身份取已冻结307个ROI的源图去重：304帧，train228、tune76，全部原始 development。只在这些索引内读取混合元数据的GT字段。旧无颜色门结果中251帧正确，用于独立分组，不能将其OCR正确结果沿用到新框。

A、B候选生成和选择全部结束后才读取该帧GT坐标。逐帧保存所有有限表候选、组件回收、峰值容量、溢出原因、两极性结构、选中身份、采样SHA和整数矩阵。OpenCV全帧连通域仅用于独立分区核对；溢出后其结果不恢复硬件候选。

评价同时覆盖全304、预声明几何域、旧251正确帧。几何域采用GT四角轴对齐范围，宽80…640、高20…160、宽高比2.3…6，两条长边绝对斜率≤0.0875，四角距画布边缘至少1像素。没有人工清晰度、遮挡、额外车牌标注，这些字段保留未知；该域不能直接称为完整可见单牌验收集。

所有候选及唯一选中候选都计算与GT四边形的IoU（0.5/0.7）、四角完整包含、角点误差和GT面积裁失比例。坐标使用像素中心：半开框 `[x0,y0,x1,y1)` 对应角点 `(x1-1,y1-1)`。

截字另作评价诊断：从GT四角取得原彩色ROI，分别生成两极性七区前景，将前景中心映回画布，统计落到候选外的每区数量；任一区超过15%记诊断标志。没有七区则未知，两极性均成功则分别报告。此掩码不是人工字符标注，清边可能遗漏真实笔画，所以 `character_clipping_confirmed` 始终未知，不以包含率或这一诊断证明“没有截字”。

定位损失按“没有唯一选中框，或选中IoU<0.5”列出全部身份；另外列四角未完全包含身份。保存每个入口的候选量、极性、overflow/ambiguity和软件耗时分布。没有现场连续视频，本轮不报告抖动改善。

## 执行及冻结

入口为 `tools/blue_plate/char_segment/run_edge_localization.py`：`prepare` 冻结身份和参数，`check-reference` 验证精确参考，`run` 执行一次完整实验。每步拒绝覆盖已有产物；`run-start.json` 阻止重复执行。结果位于 `tmp/blue-plate-char-segment/edge-localization-e0/`。所有参数和依赖源码在跑图前保存SHA；运行前后核对。

容量检查已覆盖512种3×3掩码、64个随机分区、斜对角连接、后到桥合并、6400次标签分配回收、实际256槽峰值及三类溢出。运行器另检查画布、GT坐标、完整与裁失框、七条结构反例、空图和单组件双极性、JSON及汇总。两组均使用合成数据，无模型调用。

E0是否能进入OCR阶段，需依据定位结果再由主控决定。本合同不授权调整模型、阈值或产品RTL。项目README的用法和状态不因本次研究脚本改变。
