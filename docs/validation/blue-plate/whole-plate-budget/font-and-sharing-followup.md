# 保持字形不变的最小候选与共享边界

2026-10-19，接续 [同一固件审计](same-firmware-audit.md)。本轮完成静态内容/地址验证及端口寿命分析，没有修改字体或产品 RTL，没有启动综合。结果在 [font-storage-audit.json](font-storage-audit.json)。

后续独立实现已完成，实际9 RAM与逐周期验证见[实施报告](font-compact-implementation.md)。下文保留实施前的候选分析与共享边界。

**优先安排独立的“分区单 bit 同步字库”候选。** 它只改变字库组织与选位位置，不改字形、字号、显示位置、颜色、有效ID、复位行为或一拍像素延迟；按合法 RAM 模式提出 9 RAM 目标，待 map 证明。它比缓存第三所有者改动范围小、等价关系直接，适合作为下一项可验收的资源改进。完整功能仍有更大的资源缺口。

## 1. 实际字库覆盖

读取 `tools/blue_plate/plate_display/plate_osd.v`、`plate_font.mem`、`assets.json`、`plate_defs.vh` 与生成脚本，核对字体 SHA `86a83630b7cf0d62f3e5aef2082786d57560744f93983b88307bd1128a32ff2e`。

| 内容 | 实际值 |
|---|---:|
| 原 ROM | 4096×32bit，实际 map 16 RAM |
| 字形 | 65类 + “未识别”3字 + 空格，共69个 |
| 可达行地址 | 0–2207，共2208行 |
| 后部不可达全零行 | 1888行 |
| 可达全零行 / 非零行 | 529 / 1679 |
| 唯一行 / 唯一非零行 | 756 / 755 |
| 所有墨迹范围 | x=2…29，y=1…29 |

ID 64 是“9”，65–67是“未识别”，68为空格；输入ID大于68会钳到68。空白行与重复行都是实际内容统计，没有按容量直接折算成节省RAM。

原菜单 OSD 的 1 RAM 存的是1024×8的菜单**字符编码**。文字像素来自 `glyph(character)` 的5×7组合查表，再按区域放大；它不是32×32汉字字体。共享旧字符查表会改变字形，直接替换不可用。将两份ROM放进一个模块也不会自动使它们只占原来的1块RAM。

## 2. 最小候选及映射目标

Efinix [Titanium Primitives User Guide，第21–24页](https://www.efinixinc.com/docs/efinity-quantum-ti-primitives-ug-v1.3.pdf) 明确支持8192×1、2048×4、512×16等RAM10模式。同步读可不启用额外输出寄存器；INIT按地址和位宽组织。以下是按这些端口形状提出的结构目标，不是综合结果。

### 首选：分区单 bit 同步读

目前像素为 `font[{glyph,row}][31-column]`。将column接入ROM地址，保存顺序仍为原行的bit31到bit0：

- ID 0–63：65536×1，地址 `{glyph[5:0], row[4:0], column[4:0]}`；8个8192×1 RAM10。
- ID 64–67：4096×1，地址 `{glyph[1:0], row[4:0], column[4:0]}`；1个8192×1 RAM10，未用地址为零。
- ID68与钳位后的非法ID：固定输出0。
- bank选择和blank标志与RAM读同拍寄存，输出端选择对应的已读像素；原panel/text/RGB/DE/HS/VS延迟保持一拍。异步复位时像素、标志与原输出一致。

这只需拼接地址、少量bank/blank选择，避免通用除法、乘法、字典查表和DDR。目标从16降到**9 RAM**；字库bank选择所需LUT/FF、推断或显式primitive后的真实RAM数量以及读后mux时序均待map/验证，未计入主预算。

保守对照是保留32bit行读取，将ROM显式分为2048×32与256×32，分别对应8个2048×4、2个512×16，目标10 RAM。它保留原列选位，只多分区选择；可作为单bit候选遇到工具推断/时序问题时的对照。仅缩短数组声明为2208深度，不能保证工具不会仍按4096深度组织。

重复行字典可表示为2208×10索引和756×32数据，共46,272个原始bit。但两级同步ROM会增加一拍，组合索引则可能消耗较多LUT；当前XLR余量只有92，不先选此路线。裁掉空白外框再做紧凑地址需要额外边界及地址运算，也不作为第一候选。

### 已验证与下一项验收

静态脚本已遍历全部128个输入ID × 32行 × 32列，共**131,072种组合**：原ROM、分区32bit行、分区单bit、字典重建结果逐点一致，包括空格与所有被钳位ID。字体和源码哈希未变。这只证明数据/地址等价，尚未证明时序RTL。

下一项独立验证应复制原模块为参考，候选只改字库部分，在相同输入下逐周期比较RGB和DE/HS/VS。覆盖所有字形、七个槽位、“未识别”、非法ID、panel内外边界、de变化、任意坐标跳变、active包切换、异步复位和复位释放，不能依靠“下个像素总是相邻”预取。map检查ROM初始化和模式、实际RAM数量、LUT/FF/DSP变化及组合路径；若使用已有mapped LUT仿真修正，应沿用其条件并单列。无需整机长构建即可证明这一步是否有效。

即使9 RAM目标达成，现有模块原样相加仍从232变为225，**仍超21 RAM**；完整51-bank计划从264变为257，**仍超53 RAM**。geometry本身9,687 LUT4、4,730 FF、4,300 ADD及新调度/定位逻辑的缺口没有因此消失。字库成功不能等同整机fit成功。

## 3. Canny/shape/OCR共享必须满足的所有权

| 资源 | 现有所有者与存活期 | 可串行复用的边界 | 新增需求 / 不可共享场景 |
|---|---|---|---|
| Canny cache低16KiB | Canny任务的4条4KiB图像线；shape ext请求也用tag/dirty/replacement | 当前任务完成、脏线写回完成、外部请求和DDR事务均排空之后 | 新owner寄存器、地址/数据/使能mux、响应归属、tag失效；不能在Canny运行中给OCR覆盖 |
| cache高16KiB | shape队列前缀，写后读，队列大时继续用DDR | shape的队列消费结束或取消后完成清理 | OCR不能只检查Canny state==IDLE就占用：shape可在相邻ext事务之间仍持有数据 |
| queue0…3、seed FIFO | Canny当前遍历/seed扫描 | 整个遍历结束 | 实际实例34 RAM中不全是32KiB大cache；不能按总字节盲分银行 |
| OCR权重bank | 2048×64、16 RAM，64bit一拍同步读；4个深度组×4宽度银行 | 当前K块全部消费并排空之后可重装 | 若借同一物理cache，须保持8lane/读延迟、支持重装和字节使能；现有ext是128bit缓存事务接口，不是每拍64bit直读bank口 |
| OCR部分和 | 512×32、2 RAM | K分块累计、tap2主/分支输出均结束后 | save/restore/scalar读/停顿数据必须保留；不能在两个K块之间被shape覆盖 |
| 原算法46 RAM窗口 | median/gaussian/Sobel/NMS/cleanup的帧内行数据，pixel域 | 定位完整帧处理、尾行冲刷完毕，且不再运行原边缘流时 | 多种宽深/读写模式不同；加owner、端口mux、复位/flush及跨域握手，不能把pixel50MHz窗口无条件交给core100MHz |
| reader 7 RAM与OCR IO规划7 RAM | geometry邻点取样与OCR输入/输出块 | 最后一个geometry像素和writer响应结束后，且无后续reader请求 | 需证明双向缓存寿命、错误排空；目前两个7 RAM不视为同一bank |
| capture/display FIFO、ISP、DDR PHY | 持续视频 | 当前页面切换并不终止其任务 | 不能作为OCR临时工作区 |

现有 ext_* 合同的调用者只有shape：请求数据保持到ext_done。给OCR增加第三所有者不能只加二选一请求mux；必须在任务粒度授予所有权，等待缓存和DDR完成，再允许下个所有者。取消/切页/epoch变化必须阻止新请求、排空在途事务、回报任务状态，最后释放原始帧引用。对于仍存活的数据，应保存/恢复或拒绝切换，不能静默覆盖。

“同一固件都有功能”允许在不同页面选择不同作业，**不意味着同一帧的边缘与OCR可以并行占用同一RAM**。若边缘流仍持续产出下一帧，46 RAM窗口就在使用；若Canny/shape继续分析，它们的缓存也不能借。只有明确按“完整定位 → 停止新边缘作业并排空 → 几何输入 → OCR → 释放/恢复”串行，才有生命周期不重叠的候选。保持30fps边缘作业同时又借走窗口433ms不成立；页面串行模式下的恢复与切换行为须另外验证。

## 4. 算术复用的实际边界

shape有两路signed24×24→48bit寄存乘积，加上其他表达式，实际整个实例用19 DSP；Sobel用4 DSP；OCR核心为8路signed17×signed8及共享Q31。19并不意味着可以原样替代8路MAC，也不能将它们的DSP数量直接相减。

可研究任务串行时共享同一组物理乘法器：需新增操作码、输入mux、扩展/符号规则、输出路由和延迟标签，保留shape全宽乘积与OCR累加/舍入语义；在乘积、部分和、Q31分段乘法全部消费前不能切换。Sobel属于pixel域且逐像素服务，持续边缘流时不能抢占。geometry含1 DSP，但其主要开销是9,687 LUT4和4,300 ADD；只复用DSP不能解决其逻辑成本。

因此先安排局部字库候选验证实际收益；缓存/窗口复用先交付银行和作业所有权方案，再做独立仲裁/取消/生命周期验证。资源总账继续保留unknown项，直到相应实现map完成。
