## 缓冲、常数和计算增量

以下是本分叉相对既有完整LPRNet共享方案的布局核对，不代表完整网络map或延迟通过。

| 项目 | 本候选 | 既有容量 |
|---|---:|---:|

| tap2主干A8 | 50,688B，偏移202,752 | 同上，合253,440B |

| arena总预留 | 7,015,168B | 8,388,608B |
| 新增RAM银行 / MAC DSP | 0 / 0 | 51 RAM / 同8 DSP |

tap2卷积生产两路输出时，输入槽一直存活；全部66块写完才释放输入。原上下文输出在该支消费结束后释放，主干输出继续保留到maxpool最后一次读取；池化结果21,504B写回已经释放的原输入槽。新实现不保存完整int32特征图，硬件可以让既有8 lane累加值等两路串行重定标结束后再复用。保持int32累加、int64乘积，不扩位宽预算。

每ROI额外50,688次重定标，无新增卷积MAC。为容纳两路输出，空间块从16降为12，tap2权重装载由50块变为66块，增加262,144B权重读取；额外主干A8写50,688B，分为66次768B写入。原上下文分为66次3,072B写入，合132次顺序写入。仍使用一个在途事务；未估算额外协议延迟，也未预支主干紧凑布局可能节约的读流量。

独立验证用真实ROI0数据逐块写入两个区间，核对全部253,440B、132次写入、输入保留到最后读取、消费者完成后释放及池化结果复用原输入槽。该检查通过；XLR、端口RTL、吞吐和时序仍待硬件实现验证。
