# M07：彩色边缘叠加

状态：仿真、构建、SRAM下载和板上自动验证通过；2026-10-11用户回复“没问题”，M07人工验收通过。

## 操作

```bat
camera-control.cmd --edge --view overlay --median on --threshold 32 --samples 1
camera-control.cmd --edge --view color --samples 1
camera-control.cmd --edge --view compare --samples 1
```

叠加视图显示完整1280×720原彩色图像，将当前最终Sobel边缘像素替换为纯红色`RGB=255/0/0`。非边缘像素的RGB逐位保留。已有底部参数栏仍覆盖其所在区域，增加`O=1/0`表示实际显示帧的叠加状态。`T/M/D/O`均由进入HDMI的帧头读取。

六种视图为`color|gray|edge|compare|denoise|overlay`。中值使用`--median on|off`；KEY2减阈值、KEY3加阈值，KEY0复位。默认加载仍进入灰度／Sobel对比，白平衡389/256/427、Gamma0、Bayer0。

## 实现

`compare_display.v`直接使用同一DDR像素中的RGB24和最终边缘位，合成发生在HDMI FIFO之前，不增加行缓存、帧存储或算法延迟级。显示请求在HDMI消隐期提交，并在该帧第一个DDR字到达时锁定，帧中后续请求不能改变已经开始输出的画面。

去噪帧的RGB位置保存灰度载荷，显示器继续按该帧D标志解码。切到叠加后，尚在缓存中的D=1帧仍完整显示去噪对比，待RGB帧到达后显示红边，避免将灰度载荷误当彩色。原始DDR帧头和算法参数格式保持M06定义；输出FIFO帧头的空闲位6记录实际叠加状态。

`threshold_osd.v`显示实际帧的O状态，通过已有握手快照与T/M/D一起送回调试域。新增JTAG输出`overlay_sel`，输入`overlay_active/overlay_shown`分别表示已提交请求和实际HDMI状态。控制脚本、profile、生成的debug RTL使用M07标识`0x60101007`。
