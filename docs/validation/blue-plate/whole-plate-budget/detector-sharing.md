# 检测与整牌识别共用资源：端到端可容纳性复核

**口径补充：本文历史账本未含combined gate中的颜色CNN，不能作为完整模型链路成本。完整预训练LPRNet及颜色CNN均已补账，见 [color-cnn-sharing.md](color-cnn-sharing.md)。**

后续19层depthwise八路独立输入检查见 [depthwise-schedule.md](depthwise-schedule.md)：保持同一8 DSP阵列，卷积调度降至229.776ms。本文271.104ms和对应权重流量保留为原广播方案的对照，不代表优化后的最新值；NMS最坏界不变。

2026-10-18。对象是已经下载并实测过的 `y5fu_320x_sim.onnx` 与唯一 C8-native 学生结构。**196/204 RAM 是识别侧分配目标，不是检测、识别和视频已经集成可用的结论。** C8 首轮训练尚未产生有效识别结果；本次不进入 CNN RTL，也不改变资源上限。

当前结论：保持一个 8 路 MAC 阵列、51 RAM 分配，检测和识别可通过**顺序执行、DDR 保存多分支特征、按块装载权重**共享存储。但这个结论依赖尚未验证的整数化、标量算子与控制实现。实际检测图在当前广播方式下需要至少 **271.104 ms 卷积调度**；未限制的 NMS 最坏约 **1,984 万次比较**。XLR、端到端服务时间和实际精度均未通过，不能据此宣布整机可行。

## 1. 新增证据

使用 [detector_sharing.py](../../../../tools/blue_plate/whole_plate_budget/detector_sharing.py) 重新读取真实 ONNX，关闭 OpenCV 层融合，以全零合成输入执行一次前向，输出为 1×6300×15。没有读取任何真实评测图像。

- 模型含 **435 个 OpenCV 图节点、582 条依赖边、85 个卷积，其中 19 个深度卷积**。全部输入/输出形状与主控原 `model-costs.json` 一致。
- 从真实图的 DOT 连接提取生产者/消费者，逐节点分配、末次使用后释放，验证所有读取对象仍存活、所有同时存活地址不重叠、地址不越过预留 arena。
- 每个卷积重新计算 groups、K、8 路广播周期及权重分块；总 MAC 复核为 **183,417,600**。
- 检查六个执行阶段的 51 个 RAM 银行所有权，阶段内没有重复占用。此项是分配检查，不是 RTL 端口仿真。
- Python 退出码 0，模型、成本清单、官方仓库后处理源码的 SHA-256 前后不变。完整数值和哈希见 [detector-sharing.json](detector-sharing.json)，日志为 `tmp/blue-plate-whole-plate-budget/detector-sharing.log`。

读取的参考材料包括既有 Efinix RAM primitive、TinyML generator/resource_lib 与整数 Conv 参考实现；本轮另核对 [ONNX 分组卷积规则](https://onnx.ai/onnx/operators/onnx__Conv.html) 和 [Resize 坐标规则](https://onnx.ai/onnx/operators/onnx__Resize.html)。实际 detector 导出参数是 nearest/asymmetric/floor 的 2 倍上采样，不能直接用任意双线性替换。实际源码 `hyperlpr3/inference/multitask_detect.py` 定义 RGB /255、黑边 letterbox、objectness 筛选、类别分数相乘、全候选 NMS 和坐标恢复；本次已逐段读取。

## 2. 51 RAM 逐项复查

| 分配 | RAM | 是否存在遗漏或条件 |
|---|---:|---|
| 权重 | 16 | C8 可常驻；检测模型不能常驻，必须改为可写缓存、按组装载。不能仍把这 16 RAM 定义成只读固化 ROM。 |
| bias / multiplier / shift | 4 | 312×72bit 的 C8 参数可放下；检测总参数不能全放，按层载入。当前检测最大输出通道128，单层 128×72bit 足够。 |
| 128bit 数据 RAM + tags | 7+1 | 单个 512×128 分为 4KiB 读缓存、4KiB 写块；一次一个 DDR 事务即可，不要求额外双向大队列。 |
| 工作余量 | 4 | 当前未赋予必需功能；检测后处理可占其中一个 RAM 放 6300bit 抑制标志。剩余不是已证明可填入任意新算子。 |
| 高度和 + logits | 5+10 | 已按 16/32bit 端口修正为15 RAM。四分支依次投影、立即释放高度和，不同时保留四张 tap。 |
| CTC / LUT | 2 | 仍是目标。检测 sigmoid/SiLU、OCR reciprocal、CTC exp/log 可按阶段换表，但表规模、精度与读口尚未冻结。 |
| resize | 1 | 单独不足以缓存两行 RGB1280；检测预处理必须暂借尚未使用的8个上下文 RAM。 |
| 控制 | 1 | 可放一个当前描述符，不能放435节点全部描述符。离线固定地址计划存DDR，逐节点装入。 |

**平均池化没有漏掉另一组行缓存：** 现有学生调度从 DDR 重读每个窗口，局部只保留加法和、平方和、当前高度和。对应重读已经进入原 755,056 B 轨迹。若要求窗口连续流入、不回读 DDR，必须新增或重分配行缓存，不能沿用这个数。

**动态缩放仍未完成：** 四次能量倒数、epsilon 映射、池化舍入、分支增益统一尺度、int32 logits 范围尚无训练后整数参考。能量与乘积可用标量64bit寄存器、串行乘除，不必新增整张缓存；其 LUT/DSP/XLR/周期却不是零。当前15 RAM上下文要求高度和/int32 logits不扩宽，若训练需要更宽累加须重新计数。

**CTC 不只是贪心 argmax：** 原契约还要求完整标签概率，包括 log-softmax 与15状态、35步的前向DP。两行状态约120 B可放寄存器或复用已释放高度和 RAM；真正未证的是 exp/logsumexp、舍入与阈值等价。两个 RAM 没有被完整实现证明。

**DMA 队列条件：** 保持一个在途读或写，内部接受完整 burst，再进行计算；写完成后才复用缓冲。地址、长度、事务ID、计数和响应状态用小寄存器，不需要假定两组额外128bit FIFO。代价是串行等待。若现有 DDR bridge 强制多 outstanding、跨时钟队列或最低突发长度，须按其真实接口补算；本次没有把这些未实现接口算为已经通过。

## 3. 最小共享方式

顺序固定为：**复制原帧并生成检测输入 → 检测 → NMS/候选列表 → 校正/resize → C8 → CTC → 下一 ROI**。不重叠检测和识别，不新增第二套 MAC 或权重 RAM。

检测前，两行 RGB1280 需要 7,680 B，可暂借8个上下文银行、每个按512×16有效位存储，共8,192 B。这些银行此时没有 OCR 高度和或 logits。frame_reader 已提供 RGB 像素对，1280×720 转320×180并上下各补70行黑边，应保持原 detector 输入语义；灰度复制三通道会改变模型输入，不能代替。

检测时，共用16 RAM权重缓存、4 RAM参数、8 RAM IO/cache 和2 RAM查表空间。按**16个空间点 × 一个输出通道组 × 全 K**执行；当前最大 K=576，8路一组最多4,608 B，装得下现有16 RAM。每处理下一组可停算装权重，完整特征及支路保存在DDR，不依赖额外片内部分和大缓存。不同组的输出写入同一空间块，完成后连续写回。

输出不能继续固定“一整行一缓冲”：`Concat_443` 的128×40一行是 **5,120 B**，超过4KiB。改为最多16空间点的输出块，当前最大核心拼接通道256，16×256=4,096 B，正好放下；解码头每点15×32bit时，16点只需960 B。这个变化是 DMA/地址调度适配，不是第二个执行器。

深度卷积中每组只有一个输出通道，当前一个输入广播给同组输出的方式每次只有一个 lane 有效。无需增添新单元也能执行，但不能以总MAC除8预测时间。实算广播周期 **27,110,400**，100MHz为 **271.104 ms**；已经包含深度卷积闲置lane，尚不含数据访问和SiLU等标量操作。

NMS完成后，检测特征全部释放；同一缓存装回C8权重。处理单个ROI期间不再运行检测，也不让另一个ROI占用高度和/logits。两阶段均复用描述符、DDR访问控制与标量算术。

## 4. DDR 存活峰值与地址

当前原文件是浮点模型。这里的硬件存储假设明确为：**主干中间量INT8，常量和解码头INT32**；并没有证实模型量化后准确率。按每节点独立物化，不预支 SiLU融合、view别名或原地覆盖：

| 项目 | 字节 |
|---|---:|
| 最大单个主干特征 | 409,600 |
| 图中同时存活峰值 | **1,228,800** |
| first-fit 分配地址最高点 | **1,536,000** |
| 6300条64B候选 + 两个8B排序数组 | 504,000 |
| 检测工作区与后处理预留合计 | **2,040,000** |
| 打包检测权重 | 533,952 |
| 分层 bias/scale/shift | 45,968 |
| 图常量源区 | 529,280 |
| 每节点256B描述符 | 111,360 |
| 独立保存RGB720p原帧 | 2,764,800 |
| C8权重源预留 | 16,384 |
| **以上地址预留合计** | **6,041,744** |

图峰值来自 stem 的 Conv、Sigmoid 和 Mul 三个409,600 B对象同时存在；后续长支路也通过真实消费者引用检查。原先两个64KiB识别槽不能覆盖检测图，必须改用编译好的多对象 DDR 地址表。脚本在**8MiB私有arena的相对地址范围**内检查全部对象，不表示已经从现有视频内存图获得8MiB可用区。C8临时特征区在检测工作区释放后复用，因此不再叠加。

原帧寿命不能遗漏：检测输入写完后，后续校正仍需同一原帧。最小稳妥契约是在读原帧生成检测输入时同时复制到私有DDR，完成后归还原视频帧槽；所有ROI校正读取这份副本。它额外带来一帧RGB写入2,764,800 B。另一种方法是保留原帧租约直到所有ROI结束，但当前数百毫秒执行会改变帧管理行为，须先证明长时间占用不会阻塞视频。不能在输入生成后释放原帧，又在识别时读取已被覆盖的槽。

该6,041,744 B是上述地址集合的容量，未宣称完整定点常量、C8归一化表、错误追踪区等最终布局已经冻结；8MiB与其差额留有约2.35MB空间，但必须由主控的真实DDR映射确认。

## 5. 检测流量与视频读写预算

所有流量基于真实层形状，无重试。最坏数据拍量与最坏等待时间分开：仲裁不给最低服务保证时，等待时间没有有限上界。

| 每次320检测 | 字节 |
|---|---:|
| 每条图边读一次、每节点写一次的理想物化参考，含权重/参数/常量装载/描述符 | **47,838,352** |
| 16空间点分块、逐组装权重的权重读 | **14,039,040** |
| 每次标量读取均miss且独占16B拍，输出连续写的保守情景 | **708,740,240** |
| 每次标量读取及输出均独占16B拍的更宽数据拍上界 | **931,654,928** |

后两者不是测得的平均流量。它们说明 cache/布局必须验证，不能只报约457KB权重。理想参考也不是可达到下界：当前16点分块会重读权重和激活。尚未对检测的所有地址访问执行 cache 命中率仿真，因此不填入虚构的“实际16点流量”。

连续写情景分为约 **689.580 MB读、19.160 MB写 / 检测**。检测输入的307,200 B写入、原帧读取/复制、NMS和ROI处理在此之外。

保留视频固定有效流量：

| 视频方向 | MB/s |
|---|---:|
| 读：raw读取82.944 + HDMI221.184 | **304.128** |
| 写：raw写入82.944 +结果110.592 | **193.536** |
| 合计 | **497.664** |

额外负载应按 `检测频率×检测字节 + ROI频率×OCR字节 + NMS + 原帧复制/输入/校正` 计算。OCR既有轨迹约0.755 MB/ROI；全帧读取和私有副本写入合计约5.530 MB/检测。若检测每秒10次，单是47.838 MB理想物化参考就增加478.38 MB/s，271ms卷积调度本身也已经无法达到10次/s。

128bit×100MHz的1.6GB/s是接口名义上限，不能当作可分配带宽。若采用上述宽上界并加完整NMS，单次数据量约1.57GB；即使每秒一次，加上视频也超过名义总量。这只说明**当前方案没有最坏流量保证**，不等于真实图像每次都会如此。

## 6. NMS、定位与尚未适配算子

实际源码先用 objectness>0.25 筛选，再计算两类概率与objectness的乘积，对所有保留框排序和NMS，最后恢复四边形。它没有预先限制候选数，也没有“只取两个ROI”的执行界限。

最坏6300个都通过阈值且互不抑制：

- 比较对数为6300×6299/2 = **19,841,850**。
- 完整候选64B/条放DDR需要403,200 B；两个排序score/index数组需要100,800 B；抑制bitmap为788 B，可用一个工作余量RAM。
- 13轮外部归并排序的连续读写情景约1,310,400 B；每次IoU比较各取16B框与16B索引拍的情景为 **634,939,200 B**，另有选中记录读取403,200 B及候选生成读写。
- 如果全都保留，还可能进入6300次校正/识别。只约束内存不会约束任务完成时间。

这是检测+识别无法仅靠“共享51RAM”解决的瓶颈。本轮保留原始无上限语义，不提出具体top-K或ROI数量上限。后续若研究候选截断，必须先用固定软件数据逐图比较召回与误接收，才能提出具体数值；不能暗中加入上限后继续沿用387/388结果。

其他未适配部分：

- stride2/padding、19层depthwise组寻址；当前C8检查器不能直接覆盖这些卷积。
- 69个Sigmoid及与乘法组成的SiLU，必须处理负数、缩放和限幅；不能直接当作ReLU。
- 通道shuffle：38个Reshape、19个Permute、59个Slice以及32个Concat。可用DDR物化保持清楚语义，但不得把跨通道置换全部记为免费view。
- 两次nearest/asymmetric/floor上采样；不是C8的整数双线性输入resize。
- 检测头坐标/anchor/grid缩放、两类概率、阈值、排序、IoU及坐标恢复，需明确有符号定点和64bit乘积范围。
- 学生的动态能量归一化、CTC置信度、完整性拒识；新增质量头如果最终必要，还要另计模型成本。

这些算子可复用同一MAC和标量乘除/查表通路，**不要求第二个执行器**；但相应控制、地址生成和定点验证确实增加XLR与时间。未综合前不能把它们塞进“剩8 RAM”就称已容纳。

## 7. 明确超出项与最少调整

1. **纯片内路径不成立。** 单个409,600 B特征就要400个1024×8 RAM，比保留灰度后剩余59 RAM多341。模型全部打包权重也装不进16 RAM缓存。最少调整是DDR特征存活表和可重装权重缓存，而非提高204 RAM预算。
2. **原4KiB整行写回超出1,024 B。** 改为16点块写即可保持现有7RAM数据银行；不能继续使用C8“一行完成再flush”的无条件假设。
3. **两行RGB超过单独resize RAM。** 预处理阶段借8个空闲上下文银行，阶段结束归还，不增加常驻行缓存。
4. **NMS/ROI个数没有时间上限。** 内存可移到DDR，最坏工作量仍不能满足有限时限；需要明确K/R策略并验证效果，或接受较低、非固定更新频率。
5. **XLR仍无可行结论。** 现有保留模块仅理想打包情景剩约5.9–6.8k XLR。共享不会消除新地址控制、定点算子、NMS及完整性判断的逻辑。先等C8训练根因实验和量化路径成立，再做小规模map；当前不进入重型PNR或板测。

本次产物给出共享内存的最小组织、可复查地址与保守流量边界。它没有补足整链可行性的全部证据，也没有下调原预算或隐藏检测器成本。
