# 冻结整数候选：服务时间与累计资源

2026-10-18。**当前8 DSP串行方案不能按现有500ms TTL服务受控单普通蓝牌。** 按100MHz、无CE停顿、立即消费结果计算，LPRNet已知核心调度为 **1,364.45460ms/ROI**；再加检测和颜色CNN的纯MAC，已知小计 **1,601.20216ms**。检测/颜色的量化、非卷积、DDR等待、输入准备、几何和置信度仍在此之外。单独LPRNet的Q31内部计算899.26832ms已超过TTL，结论不依赖未知开销的估计。

这是从冻结参数和已验证RTL契约推导的计数，**不是板上延迟实测，也不是所有可能架构的时间下界**。100MHz尚未PNR验证。首版场景收窄为清晰完整无遮挡单蓝牌，并不会减少固定网络的输出数量或改变包时间戳。没有修改TTL、确认次数、模型或门限。

复跑：`D:/Python/python.exe -B tools/blue_plate/whole_plate_budget/service_cost.py`。产物为 [service-cost.json](service-cost.json)、[逐层CSV](service-cost-layers.csv)；源文件SHA与最终校验见 [service-cost-validation.json](service-cost-validation.json)。脚本只读取配置、参数、图形状和既有报告，不运行图像、训练、全网map或板卡。

## 1. LPRNet逐项计数

脚本读取冻结 `quantization-tap2-fork/integer-config.json`、`integer-parameters.npz`，逐通道使用真实shift；16个卷积按原图尺寸，包括原顺序 `container.0`。tap2新增64通道是额外重定标，未重复计算卷积MAC。总计 **1,376,576个Q31输出**：原15层主干1,320,992、projection 4,896、tap2附加50,688。

Q31每次接受后19+s拍，另计请求与消费各1拍。最终卷积组先save，逐有效lane restore，再送标量；tap2第二路使用已锁存原值，不再次restore。save命令加8拍写为9拍；restore命令加16拍读/回填为17拍。尾4lane组只做4次恢复，save仍保存8字。该调度与冻结最小对接合同一致，没有预支256bit暂存或标量读口。

| 已精确计数的串行动作 | 周期 | 100MHz时间 |
|---|---:|---:|
| 原顺序卷积MAC | 18,189,792 | 181.89792ms |
| Q31固定19拍部分 | 26,154,944 | 261.54944ms |
| Q31真实shift逐拍右移 | 63,771,888 | 637.71888ms |
| Q31请求接受、结果消费 | 2,753,152 | 27.53152ms |
| 最终输出组save | 1,492,272 | 14.92272ms |
| 每个有效原输出lane restore | 22,540,096 | 225.40096ms |
| 每组首次bias load | 165,808 | 1.65808ms |
| 每K段最后一次权重读取排空 | 166,456 | 1.66456ms |
| K3328段间save/restore | 16,848 | 0.16848ms |
| 分块卷积权重写入bank，按有效64bit字 | 1,194,204 | 11.94204ms |
| **LPR已知核心合计** | **136,445,460** | **1,364.45460ms** |

MAC包括每个K项的issue；最后一次退休另计drain。Q31本身的两次临时权重写、两次load/issue/drain已在19拍内，未重复收费。卷积权重DDR有16B对齐padding，但bank仅需写有效64bit字，因此bank写周期不简单等于DDR字节除8。

K3328仍按2048+1280、16空间点调度；tap2双输出采用12点块，66块，增加262,144B权重重读。当前projection保持每个 `(class,h,t)` 完整K516→Q31/zero/饱和→高度和，纯projection为334,368个8lane MAC周期、4,896次重定标、185,760B权重读取。全LPR权重读取9,561,760B与模型新部署审计相符，没有沿用旧FP64高度换序的时间与缓存数字。

逐层完整数据在CSV，重定标内部时间最大的三层为：tap2主分支149.98104ms、`backbone.4.block.6` 143.46000ms、`backbone.8.block.6` 140.33448ms。它们输出数大，权重文件小不代表服务成本小。当前不因ReLU后的零或零权重通道跳过请求；这些短路尚未实现。

## 3. DDR、缓存与仲裁

三模型分块权重读取合计 **21,714,864B**，元数据读取 **132,176B**。两者是当前分块布局计数，不代表激活流量。LPR有效MAC输入字请求为18,034,656次；在原tag→data→MAC完全串行、全hit情景中，LPR需额外36,069,312拍，检测/颜色现有同口径缓存动作合计再加46,792,746拍，已知情景总计变为 **2,429.82274ms**。这不是所有流水架构的下界，若重叠访问须另验证端口和依赖。

| 无重试、每标量miss占16B且输出连续写的payload情景 | 字节 |
|---|---:|
| 检测：沿旧全图流量账本，更新depthwise权重重用 | 706,090,080 |
| LPR：有效MAC输入、池化、两遍context、特征写、权重和参数 | 361,520,608 |
| 颜色CNN：既有全图账本 | 17,672,896 |
| **合计** | **1,085,283,584** |

检测/颜色旧账本已含部分描述符与常量访问，LPR项没有描述符/CTC；三项合计不能声称覆盖所有流量。它是无重试数据拍情景，不是测得的cache miss率或整个系统严格流量上界。LPR项包含1,596,288B连续特征写及37,184B上下文区域；projection A8直接归约到片内logits，不另物化DDR。

外围另有原帧读加私有副本写5,529,600B、检测输入写307,200B、校正RGB写43,008B、两种输入写6,768/27,648B，以及校正57,344次邻点取样。输入缩放读取、几何cache miss、HS、描述符及取消/错误处理尚无完整总线轨迹。既有frame_reader的38.72104ms来自带指定气泡/背压的仿真夹具，不能当新仲裁下的物理延迟或普遍下界，本次没有加进核心小计。

连续视频保留有效流量497.664MB/s；128bit×100MHz名义带宽1.6GB/s，减去视频得到的1.102336GB/s也**不是可保证的推理带宽**。即使假设其全部可用，上述payload情景仍需984.531ms纯数据时间。是否与计算重叠、burst效率和DDR响应等待均未验证，不能直接给出端到端有限上界。

实际读取 `frame_store_dma.v`：读侧按显示FIFO水位与read_turn选择，写侧在capture/result及可选Canny间调度；现有接口没有完整tensor DMA请求者或推理带宽服务合同。因而当前无法给出推理最大等待。来源时间戳、帧租约/私有副本寿命也不能用服务完成时间替换。

即使真实画面只有一块牌，检测前端仍有6300候选上限；原实现没有预先Top-K。最坏19,841,850个NMS配对、约634.94MB配对访问及排序开销仍需处理。不能由“单牌”场景直接推定NMS只处理一个框。

## 4. 原显示确认与TTL

直接核对 `plate_confirm.v` 与 `plate_display_state.v`：TTL=500ms，fresh条件严格为age<500。每个合格包将support_time更新为该帧原时间戳；下个包到来前，如果当前时间距support_time已达500ms，确认状态先被清除。三个不同且递增frame、同号/同框/同配置的有效观测才确认。

设源帧到结果的服务延迟为L，连续源帧/结果间隔为P，稳定无背压时至少要求 **L<500且L+P<500ms**。顺序复用一套引擎时P≥L，因此必须L<250ms；不是简单要求三次完成总时间小于500ms。既有10场景RTL证据已验证249/249可确认、250/250不可确认，以及400/90可确认、400/100不可确认。显示域还在帧边界再次检查fresh，跨域/背压只会减少剩余时间。

当前仅Q31内部就899.26832ms，结果自身已过期；既有串行部署不具备服务条件。即便把全部重定标、搬运和非卷积理想化为免费，三模型纯MAC仍为418.64548ms，顺序250ms条件也不满足。本文未放宽TTL、降低确认次数或用新时间戳掩盖结果年龄。

采用实际彩色几何map，较旧几何增加192 LUT4与68 ADD。Q31 map已经包含MAC、权重bank与部分和，禁止再把前三个模块重复相加。

| 彩色geometry | 9,687 | 4,730 | 4,300 | 2 | 1 |

视频底座既有place为24,090 XLR、106 RAM10、85物理DSP。实际map加总对应149 RAM10、97 DSP；再计外置灰度14 RAM分配与51 RAM引擎尚未映射的33 RAM，目标为196/204 RAM，余8。引擎18 RAM是已map的权重16+部分和2；参数4、IO7、tag1、工作余量2、height9、logits6、tables2、resize1、control1共33仍是分配目标，不能漏掉其控制逻辑。DSP97/128余31不等于可用XLR足够。

[Ti60官方结构](https://www.efinixinc.com/docs/titanium60-ds-v2.7.pdf)允许LUT/Adder与FF打包，LUT与Adder也不能视作同一个运算槽免费重叠。以下保持视频已放置24,090 XLR不变，对其余映射单元计算**条件打包情景**：

| 条件 | 总XLR情景 | 对49,248余量 |
|---|---:|---:|
| 跨模块FF理想打包：24090+max(LUT+ADD,FF) | 45,055 | 4,193 |
| 模块内FF理想打包：24090+Σmax(LUT+ADD,FF) | 46,000 | 3,248 |
| FF完全不打包 | 55,036 | −5,788 |

这些不是最终PNR上下界，也没有把LUT+FF+ADD简单相加后冒充实际XLR。后续优化、fracturable映射、复制和布线可改变占用；更关键的是33 RAM对应的算子/缓存/参数/DMA控制、模型输入准备、非卷积、NMS、置信度、整链接入尚未map，没有有限可信的整机XLR上界。当前只能确认剩余理想空间约3.2k…4.2k，不能批准继续堆叠算术块。

## 6. 一个最小提速候选及它的效果边界

本轮重读已下载CMSIS `arm_nn_requantize` 的全宽乘积/可变移位实现，以及LiteRT `QuantizeMultiplier`；结合本模型floor商/RNE契约，选择**只比较将逐拍SHIFT替换为固定延迟的全宽算术右移+guard/sticky归约**。保留同一8 DSP、10局部积、原始值保存与精确RNE；不复制CMSIS的舍入规则，不同时实现其他候选。

若理想化为1拍，节省 `Σ(s−1)=62,395,312`拍，即623.95312ms。LPR核心由1364.45460降至740.50148ms，三模型已知小计仍为977.24904ms，**仍不满足500ms结果新鲜度，更不满足顺序250ms确认条件**。增加的桶形移位/归约LUT和100MHz路径尚无map证据，不能在仅余3.2k…4.2k的空间里提前计为可落地收益。

逐lane整组restore也是已知大项225.40096ms；仅省掉每组第一lane那次不必要restore，理论上只能再减28.18736ms。本项只作计数敏感性，没有改接口或实现新缓存。结论是：最小Q31算术提速值得在需要该算术核时验证，但不能作为整链服务问题的充分方案。下一决策应先确定如何在原预算及固定精度合同下同时降低串行服务量/重复检测工作并形成可验证调度；若要改变网络、检测频率、并行度或显示合同，应另行授权和验证。本轮止于可追溯核算，不自动实施这些扩大范围的变化。
