# 颜色 CNN 相对 HS＋原边界门控的单项消融

2026-10-18。**去掉颜色 CNN 后，开发集307 ROI／304帧的候选、选择和接受结果全部不变，仍为250正确、1错误、53拒绝。** 但已有绿色改色负例中，有6个裁片通过HS、被CNN独立排除；因此“开发正例没有增量作用”不能推导为“HS能够替代CNN”。这6个裁片没有当前整数OCR／Q30结果，本报告不将它们计为当前模型新增误接受，也不批准替换现有combined。

## 比较口径

只消融 `color_class == 0`。其他条件保持原值：

```text
baseline = CNN_blue AND (blue_hs > yellow_hs)
           AND (corner_margin >= 1) AND (box_margin >= 1)
ablated  =             (blue_hs > yellow_hs)
           AND (corner_margin >= 1) AND (box_margin >= 1)
```

颜色和HS均来自**原生裁剪**的冻结字段，不换成224×64裁剪后的颜色结果。HS条件为OpenCV HSV中蓝色100<H<140、黄色15<H<40，且95<S<255，严格比较两类像素数；没有增加占比、最小像素数或其他阈值。

307条现有整数OCR的字符串、语法、Q30区间不变；先按门控和合法七字筛选候选，再用原 `rank_candidates` 排名，最后按原Q30阈值判断。区间未决规则不变。标签只用于统计正确与错误，不参与候选选择。重建baseline逐帧与冻结Q30结果完全一致。

只使用开发记录及已见开发负例；共享JSON容器中的validation条目在分析前按split排除，没有用84作比较或选择，没有读取112。没有读取图像或NPZ输入，没有新推理、训练或阈值拟合。

这些已评分ROI均满足“HS通过则CNN为蓝色”。在边界字段完整的帧候选上，两种门控逐项相同；保持相同OCR和候选时，去掉CNN不会改变它们的选择集合。这个结论不需要把旧OCR冒充当前OCR。

**当前整数模型在这些负例上的错误接受数没有测量，记录为null。** 1022个ROI的旧OCR来自 `FixedLPRNet` 的原FP32前向，不能代替当前tap2分叉W8/A8模型。旧FP32的native组合在304个开发遮挡帧中已有56次接受；这些既有案例完整保留在 `negative-historical-frames.json`，不能改写为当前模型结果，更不能写成零误接受。

96个真实裁片的 `boundary_pass` 是null，原诊断程序仅在“下游裁片”口径中允许跳过该条件；本报告保留null，不补成True。由于其中通过HS的裁片也都被CNN判蓝，颜色条件之间没有差异，但完整帧边界及完整流水线接受仍缺证据。

## 实际核对的成熟实现

本轮重新读取已有下载的 HyperLPR 固定提交 `9307450f7b7915be18f23a539ec05b41fe6629f4`，并对照原下载manifest核验文件SHA：

- [classification.py](https://github.com/szad670401/HyperLPR/blob/9307450f7b7915be18f23a539ec05b41fe6629f4/Prj-Python/hyperlpr3/inference/classification.py)：resize后除255，float32、CHW，调用分类模型，不在分类器内部设置蓝色置信度阈值。
- [pipeline.py](https://github.com/szad670401/HyperLPR/blob/9307450f7b7915be18f23a539ec05b41fe6629f4/Prj-Python/hyperlpr3/inference/pipeline.py)：原生透视裁片进入分类器；上游先做文本类型判断，UNKNOWN时以argmax确定颜色类型。
- [typedef.py](https://github.com/szad670401/HyperLPR/blob/9307450f7b7915be18f23a539ec05b41fe6629f4/Prj-Python/hyperlpr3/common/typedef.py)：颜色分类ID为蓝0、绿1、黄2。

本项目的冻结评估路径由 `probe_hyperlpr_fullframe.py` 独立对每个原生裁片执行96×96分类，存下argmax；`pretrained_new_rois.frozen_gates` 取这些字段，与HS和原始浮点坐标边界相与。当前整数OCR不会改变既有颜色字段。实际读取的本地源码及数据SHA全部写入 `source-freeze.json`；没有新增广泛调研或新的颜色实现。

## 结论及交付

受控开发蓝牌集上，CNN没有独有的接受／拒绝贡献；已有全帧编辑及真实诊断颜色字段上也未发现独有排除。**绿色改色裁片的6个反例表明，现有HS规则不能被当作CNN的等价替代。** 现有证据尚不能决定当前整数流水线能否删除CNN，缺少的是这些颜色分歧样本的当前整数OCR及对应完整门控链结果。本次不新增条件来处理它们，不批准替换，也不开始颜色模型量化。
