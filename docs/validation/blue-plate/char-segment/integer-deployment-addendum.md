# 冻结分叉模型的整数部署补充合同

2026-10-18。本文补充硬件对接，不改写既有模型、量化参数或冻结文档。主控已复核开发结果，随后84张确认得到base组合70／0／14，无FP32正确接受损失和新增错误；开发集仍保留1个新增错误接受。首版范围为受控机位、清晰完整无遮挡单普通蓝牌，遮挡拒识后续改进。

## 1. 原顺序projection：不能交换量化与高度和

冻结候选每个 `(class,h,t)` 的顺序是：全部516项完整int32内积及一次偏置 → 逐输出通道Q31重定标 → 加zero=63 → 饱和到int8 → 对4行的 `(q−63)` 求和。输出int16 `[68,18]`，尺度 `0.2953726375804228`。RNE和饱和是非线性运算，不能用此前FP64线性重排的验证替代。

| 项目 / ROI | 高度提前交换的旧预算 | 本候选原顺序 | 增量 |
|---|---:|---:|---:|
| projection有效MAC | 631,584 | 2,526,336 | 1,894,752 |
| projection八输出通道调度周期 | 83,592 | 334,368 | 250,776 |
| projection重定标/饱和次数 | 1,224 | 4,896 | 3,672 |
| projection权重读取 | 74,304B | 185,760B | 111,456B |

全LPRNet原顺序有效MAC为144,411,264，八输出通道调度18,189,792周期，100MHz下**纯MAC小计181.89792ms/ROI**；相比高度提前交换多2.50776ms。这不含重定标宽乘法、保存/恢复、池化、能量除法、CTC、DDR等待。加上已冻结tap2分叉的权重读取增量262,144B后，沿用同样分块口径的全模型权重读取为9,561,760B/ROI。

### 保持51 RAM的最小存储方案

逐tap先遍历均值池窗口，统计整数能量E；E确定后第二遍重读tap并重算窗口和，按冻结gain生成归一化A8。四支A8保留在DDR，待四支齐备后按原516通道顺序执行完整projection。无需保存四张原始大tap，也不对各支单独限幅后相加。

| 支路 | 逻辑形状 H×T×C | DDR区域偏移 | 16B对齐行距 | 分配 |
|---:|---|---:|---:|---:|
| 0 | 4×18×64 | 0 | 1,152B | 4,608B |
| 1 | 4×18×128 | 4,608 | 2,304B | 9,216B |
| 2 | 4×18×256 | 13,824 | 4,608B | 18,432B |
| 3 | 4×18×68 | 32,256 | 1,232B | 4,928B |
| 合计 | 37,152个有效A8值 | — | 含32B padding | **37,184B** |

四支分区是逻辑concat的分段存储；projection取数地址跨支切换，顺序与原NCHW通道拼接一致，不要求再复制成物理concat。额外区域来自既有8MiB arena余量，预留总量由7,015,168B变为**7,052,352B**，不增加两个256KiB主干槽或片内RAM银行。

projection每组8输出通道、K=516，权重4,128B可放现有16KiB权重bank；72空间点按16点分5块。每个完整K完成后立即重定标，向原logits银行累加 `(q−63)`；16空间点×68输出的A8写块最多1,088B。最终高度和只有2,448B，可放既有6 RAM logits分配中，不要求同时保存4,896个int32 projection结果（19,584B）。该方案没有在DDR增加全projection部分和缓存。

两遍窗口的加法数为2,101,248，较旧单遍1,050,624增加一遍。还需四支能量统计、四次整数除法、37,152个归一化输出、37,184B区域的写入与projection读取。这里只精确核算窗口加法和布局；未做完整cache轨迹，不能把有效字节当作DDR总线流量或延迟。

`audit_integer_deployment.py`用真实ROI0独立NumPy int64/Fraction重算全部4,896个projection输出，再高度求和，逐元素匹配冻结候选；四个DDR分区真实A8值按行距往返一致。尚无此调度的RTL/端口验证或整机map。

## 2. 双分叉保存原int32，显式处理MAC状态破坏

已读实际 `mac8.v`：8条lane是signed17×signed8→可load的int32累加；load优先于valid。**把它用于Q31宽乘法会覆盖卷积psum**，不能仅让流水“等待”就保证原值保留。

最小对接顺序：

1. 完成当前输出组的全部K段，排空权重读和MAC更新。K=3328必须已完成2048+1280两段；不能在中间段重定标。
2. 使用既有2 RAM部分和bank的一个32B slot，保存8个原始int32。实际 `psum_weight_mac8.v` 提供save/restore、busy/done与冲突报错；该slot在两路结果全部消费前不得覆盖。此时K分段部分和已结束，不重叠占用同一slot。
3. 处理每个原输出lane前restore该组，锁存当前lane的原int32到一个32bit标量寄存器，再装零seed执行宽乘法。普通lane做上下文一路；原通道0,4,…,252做上下文和主干两路，两次都从这个原值开始，不能让第二次使用第一次的乘积或A8。
4. 两路写块均接收后才释放slot并允许下一输出组覆盖。rst/abort取消当前组及其两路结果有效位，不能保留一半分叉结果。

在当前完整8-lane restore接口下，最低风险方案是每个原lane恢复一次整组，最多8次restore/输出组；一次save串行写8个32bit，restore逐lane读/捕获至少16个有效时钟步骤，另计命令和停顿。不要把32B容量小误当作保存/恢复没有代价。若以后加独立标量读口或8×32寄存器缓存，应另核对XLR和接口；本轮未实现。

### signed32×Q31不能直接塞进17×8端口

给出一个使用现有端口、无新增DSP的确定分解。令 `a=a_lo+2^16*a_hi`，其中a_lo为uint16、a_hi为signed16；`M=sum(m_j*2^(7j)), j=0..4`，每个m_j为0..127。则：

```text
p = Σ_j (a_lo*m_j << 7j) + Σ_j (a_hi*m_j << (16+7j))
```

uint16正数65535必须零扩展到signed17；a_hi符号扩展到signed17；7bit乘数以signed8非负形式送入。10个局部乘积各自能放int32，用8 lane分两批，每批先load零、再一次valid MAC，然后读取并以**signed64移位加法**组合。部分积绝对值最大8,322,945，不允许把最终64bit积压回MAC的int32寄存器。

两批至少需要2次load、2次有效乘法命令，还要读出10个结果、移位加法和RNE步骤。软件1049项随机/边界检查全部与Python精确乘法一致，包括INT32_MIN；这不是RTL通过。现weight-bank包装器没有直接weight旁路，可在完整K结束并排空后，暂用该固定网络当前权重块末尾两个空闲地址2046/2047装两批7bit乘数；本网络其他K≤516，K3328的最后一段K=1280，因此这两个地址不与当前有效权重相交。需补控制和周期检查，不能假称已有包装器已支持整套重定标。

组合后的signed64按冻结shift做一次最近偶数舍入，再加输出zero和饱和。不得换成CMSIS默认双舍入。新64bit移位/加法器、控制器、参数bank和临时weight写入的XLR/时序/吞吐尚未验证。

上下文还有另一种宽乘：非负窗口和v最多14bit，gain保守最多53bit。可把gain拆成8个7bit段，用同一signed17×signed8阵列求8个局部积，再以uint64组合；不能截gain为int32。整数除法分子最多53bit、能量最多41bit，使用全宽整数RNE；E=0明确报错。原上下文数学界保证最终v×gain小于2^53，但不代表原17×8硬件一步能算出该乘积。

## 3. 两种八lane向量含义不能混用

首候选 `real-mac-vectors.npz` 是**一个输出点积的K项每8项分组**，每周期之后只有一个归约总和。它适用于检查八个乘积再归约的核，不能直接当现mac8的八输出通道psum期望值。

新增 `tmp/blue-plate-char-segment/integer-deployment-audit/output-channel-mac-vectors.npz` 与JSON按实际mac8语义提供：**每周期一个K项，同一activation广播，8个lane分别累加8个输出通道**。选真实ROI0的tap2和container，首/末空间点、首/末输出组，共8组、2,320周期；container末组只开4个lane，tap2每组主干分叉取lane0和4。

NPZ字段：`activation[K,8]`为signed17语义的int32容器，`weight[K,8]`为signed8，`lane_mask[8]`、`seed[8]`及`psum_after[K,8]`。先load含zero修正的bias seed，再按K顺序每拍MAC，逐lane比较；没有沿lane维求和。它们是研究回归向量，不是产品ROM。软件点积核对通过，未替硬件窗口运行RTL。

## 4. 固定网络的置信度接口与一个有限精度方案

当前剩余浮点包括logits乘常数尺度、log-softmax的exp/求和/log、CTC log-domain动态规划的logsumexp，以及最终 `exp(logP/7)`。贪心本身可直接比较int16，正尺度不改变顺序；相等取最小类ID。保持68类（包括I/O）、blank67，先合并相邻重复再去blank，合法七字才进入接受和候选排序。

实际参考：已下载LiteRT `softmax.h`，读其减最大值、定点exp、求和/倒数及int16 LUT路径；同时重读此前下载的PyTorch `LossCTC.cu`，核对三路状态转移、重复字符禁止跳两状态及末两状态合并。文件和SHA见研究目录及audit report。LiteRT输出8/16bit概率不是本模型CTC精度已经通过的证据，也不能更换本模型RNE。

**只提出一个待验证方案：Q30概率区间DP，固定阈值不变。** 本轮没有运行它替换置信度、生成新的接受结果或搜索位宽。

- 输入int16 logits `[68,18]`，按固定zero63可证明每项[-764,256]，与每列最大值之差在[-1020,0]。尺度是冻结binary64常数s，不重新标定。
- 离线对 `exp(-d*s)` 建向外取整的Q30下/上界。d=0精确为1；d=1..70用表；d≥71统一有界为[0,1]个Q30单位，因为 `exp(-71*s)<2^-30`。表只需71×uint32=284B的下界，非零d上界为下界+1；生成器必须以独立高精度带界计算验证，不能把截断尾部当作精确零。
- 68项exp和最多37bit。用下界分子/上界分母及上界分子/下界分母做向外整数除法，得到每个发射概率的Q30区间；移位后的分子最多61bit，可用uint64。每列至少一个最大项=1，分母不为0。
- 合法七字CTC扩展为15状态、18时间步。每个状态最多累加前三个状态，再乘当前发射概率；上下界分别向外舍入。状态概率有界于[0,1]，可据此截紧区间；三个上界和最多32bit，乘Q30最多62bit。两行、上下界、15状态共240B。状态转移和重复字符规则与原CTC一致，不做beam或字符独立近似。
- 末两状态概率和的区间与固定 `tau^7` 比较，避免log、七次方根及最后exp。tau就是现门限的精确binary64值；阈值区间由它离线生成，不从84选点。合法候选的P排序与分数排序数学单调等价，同分仍取较小ROI索引；有区间重叠时必须标为“未决”，不能静默拒绝、加规则或擅自改变tie结果。
- 已释放上下文阶段后，现2 RAM的CTC/LUT目标可分别放284B表及临时exp/DP状态；logits仍放原银行。Q30 DP需要uint32×uint31的64bit积，可用上节分段方式，a_hi改为零扩展uint16。不能把它计作一次原17×8 MAC。

验证门槛：先证明LUT所有1021种差值的区间有效，检查重复字符、blank、零路径及接近阈值合成案例；再只读冻结307dev与本次85条校准logits，要求原浮点CTC概率落入区间、固定接受/候选排序全部确定且一致。记录所有未决项；若Q30不足，先汇报误差证据和额外位宽成本，不连续搜索。84确认输出保持冻结，不能利用该步骤调模型或阈值；112仍关闭。

浮点exp的舍入与同分处理也须逐项对照冻结输出；上述数学单调关系不能代替边界位精确检查。

本次84的合法候选中，最近的 `|P−tau^7|` 约0.00033331256，只作为后续误差核对数据，不能据此宣称Q30方案已通过。当前缺口仍是完整整数置信度、宽算术控制、精确原顺序projection调度及整机资源/时序验收。首版范围调整不自动放行这些未验证部分。
