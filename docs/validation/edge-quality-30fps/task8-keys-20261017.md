# 任务 8：板上调阈值与轮廓降噪

## 当前候选

最终候选采用中值 + 3×3均值平滑，不增加窗口缓存；普通Canny保留原3×3高斯。实现复用窗口与加法器，在识别配置位为1时用九像素均值。参考实际读取的 [OpenCV CannyDetector_Demo.cpp](https://github.com/opencv/opencv/blob/4.x/samples/cpp/tutorial_code/ImgTrans/CannyDetector_Demo.cpp) 第29行 `blur(...,Size(3,3))` 后运行Canny。

双高斯版本资源80.98%，简化帧标签后的版本81.35%，都未通过原20%资源余量检查，因此没有采用。帧标签简化已撤销，恢复原流水线传递。以下保留试验依据和结果，不能将双高斯的测试数据套用到最终候选。

当前候选的同组16帧合成噪声比较：圆的相邻帧变化像素3101.4→1039.1，矩形3505.3→1318.2；离轮廓噪点分别1565.3→468.9、1649.1→481.3，一像素邻域覆盖率均100%。96帧RTL逐像素测试已通过。板上效果尚未验收。

## 实施前判断

用户确认：20 ms / 3.032× 改为约 30 ms / 2.021× 后，抖动没有明显改善。停止通过电脑试调摄像头，改为 KEY2/KEY3 现场调整任务 8 阈值。

当前任务 8 使用中值、一次 3×3 高斯、Sobel 梯度、NMS、双阈值和全帧滞后连接。KEY2/KEY3 原来只关闭/开启识别，阈值按键仅在任务 5 生效。

阅读的成熟实现：

- [OpenCV smooth.dispatch.cpp](https://github.com/opencv/opencv/blob/4.x/modules/imgproc/src/smooth.dispatch.cpp)，`getGaussianKernelBitExact` 和 `createGaussianKernels`：3 点核为 `[1,2,1]/4`，5 点核为 `[1,4,6,4,1]/16`，可分离处理。
- [OpenCV Canny](https://docs.opencv.org/4.13.0/da/d22/tutorial_py_canny.html)：先平滑、再计算梯度；高阈值选种子，低阈值保留相连弱边缘。

已通过网页读取实际源码。PowerShell 和 curl 下载均遇到本机 TLS 凭据错误，未取得本地副本；没有把第三方源码复制到 RTL。

方案：复用现有高斯模块，在识别任务中再平滑一次。两次 3×3 在内部区域的未量化核等效于上述 5×5；实际每级各自四舍五入、边界各自复制，不能宣称与 OpenCV 一次 5×5 逐像素相同。保留原彩色载荷，不修改其他页面的滤波结果。不增加整帧历史缓存或显示拖影。

按键沿用现有消抖、长按连调和帧边界提交：任务 8 步长 4，进入自动识别，并保存该页调好的阈值；任务 5 步长仍为 16。

初步软件比较：固定 192×192 实心圆/矩形，前景 65、背景 175，独立高斯噪声标准差 12，16 帧，T=56，低阈值比 1/2。两次平滑后圆形相邻帧边缘变化像素均值由 3101.4 降到 255.8，矩形由 3505.3 降到 504.2；允许一像素邻域的轮廓覆盖率均为 100%。这是合成噪声结果，不代替板上实拍验收，也不证明相机移动或灯光闪烁已解决。

后续验证：按键饱和/长按/重新进入、RTL 逐像素与随机反压、共享 DDR 与识别集成、综合时序与资源，再由用户按键比较实拍轮廓。

## 实机发现与追加修复

初次下载时，直接VIO版本号为04，但分页状态里的重复常量仍为03，正式控制脚本拒绝初始化。已修正分页常量，并增加两处RTL与CLI版本号一致性测试。临时初始化工具在 `tmp/task8-key-tuning/`，先核对直接VIO为04；正式控制脚本没有放宽版本校验。

实机进入任务8后，采集计数持续增长，但处理计数停在5900，识别请求为1、显示识别为0，UI报TIMEOUT；此时不能把“可调阈值”当作已经在实机完成。追加每帧形状计算4,000,000周期预算，在100MHz下约40ms；超时等待当前内存事务完成后清空结果、置overflow并结束本帧。带延迟响应的RTL检查通过：不会提前发布，有明确过载标记，下一帧能恢复。中等分辨率实际共享缓存集成也通过。
