# 蓝底颜色证据候选交接

状态：`hs-blue-over-yellow-v1`，离线候选。未接RTL、生产推理或板卡；不代表G1通过。开发后的84张校准确认结果与原全帧残缺对照记录见[拒识报告](../validation/blue-plate/mature-rejection.md)。

确认结果：84张校准为72正确/0错/12拒，比原.8门控多拒1张（sample57）；1164张原全帧残缺变体仍全部拒绝。加上开发结果，388张为331正确/0错/57拒。原参考逐候选四角、文字、分数均重现一致，候选没有重新调参。

## 固定算法和来源

在原HyperLPR参考流程全部门控之后增加一个必要条件：`blue_count > yellow_count`。

| 项目 | 冻结定义 |
|---|---|
| 输入 | 同一候选的原生透视矫正彩色图，uint8 BGR；在识别48×160和颜色96×96各自缩放之前统计 |
| H/S数值域 | OpenCV uint8 `COLOR_BGR2HSV`，H为0—179，S为0—255 |
| 蓝像素 | `100 < H < 140 && 95 < S < 255` |
| 黄像素 | `15 < H < 40 && 95 < S < 255` |
| V | 不参与门控，无V均衡、亮度门限或颜色比例门限 |
| 接受 | 原门控通过，且蓝像素数严格大于黄像素数；相等或全0均拒绝 |
| 候选选择 | 对每个候选独立门控，再从合格候选中选择原识别均值最高者；不按号码、来源或样本编号设例外 |

颜色范围来源是实际读过的[EasyPR固定提交core_func.cpp](https://github.com/liuruoze/EasyPR/blob/a0a9f3c3f612e7c8d9046bd9c5770249cfb86850/src/core/core_func.cpp)。原`colorMatch`还检查均衡后的V；原`plateColorJudge`使用>.45覆盖率；本候选明确删去这两项并比较蓝黄计数，**不是EasyPR原有完整算法**。未采用其`getPlateType`的未知颜色默认BLUE行为。源码及Apache-2.0许可证已下载，见`tmp/blue-plate-normal-g1/mature-detector/easypr-judge/color-source-download.json`。

本轮运行OpenCV 4.13.0。冻结清单SHA256为`260ca18725c3e1f6b68cf652973641b209126cdd788b7ee0c9ba8d00a99211df`。

本轮执行来源：

- 原流程：`tools/blue_plate/hyperlpr_reference.py`，保持未改动。
- 颜色证据参考：`tools/blue_plate/diagnose_color_evidence.py::color_evidence`。函数同时计算其他对照统计；本候选仅取`blue_hs`和`yellow_hs`计数，不要求实现其他分支。
- 候选组合接口：`tools/blue_plate/confirm_color_candidate.py::add_color_evidence(frame, result, warp)`。
- 冻结参数、全部依赖和模型哈希：`tmp/blue-plate-normal-g1/mature-detector/color-candidate-confirmation/candidate-freeze.json`，在确认推理前写入。

## 对模型窗口的接口

原`FrozenReference.run_frame`仍返回原候选及原选择。组合接口仅附加`blue_count`、`yellow_count`、`blue_evidence_pass`、`candidate_accepted`、`candidate_rejection_reasons`，并另返回`candidate_selected`，保留原结果可逐图对照。图像级输入仍是1280×720 BGR；`run_image`的letterbox规则也保持原样。

参考原门控为：普通七位格式、颜色分类蓝类、CTC保留字符均值≥.9、最低保留字符概率≥.8、原始浮点框及四角距画面边缘≥1像素。每个字符的概率取原贪心CTC去重后保留时刻；未知token显式拒绝。

`.9/.8`是当前教师的概率门控，不能直接当作学生、量化模型的已校准门限。学生更改输出类别、CTC时间长度、归一化或置信计算后须重新建立相应证据。颜色计数与识别分数独立，也不把颜色通过当作字符完整标签。

样本边界：304开发、84校准、112留出；后者继续封存。原21张合成失败中16张来自开发、5张来自校准，已有manifest记录用途。新增真实黄牌、背景和截断候选是诊断材料，不自动转入训练；任何教师猜测均不得作为残缺候选的完整号码标签。保持31省覆盖要求。

## 对资源窗口的接口

本候选算法需要两个逐候选计数器和一次严格大小比较；不要求新的CNN、V直方图或额外保存画面。像素流只有被实际消费时才累计，每个候选开始清零，收到完整结束后才产生决定；取消、复位或错误不得保留上一个候选的计数或有效结果。统计结果需与原frame_id/epoch/generation及候选标识保持关联，沿用现有生命周期契约。

计数宽度由明确的最大输入像素数决定：`ceil(log2(Nmax+1))`，不能溢出后当正常结果。224×64图上每个计数器至少14位。原先冻结证据使用原生可变尺寸裁剪；后续已完成既有Q32/Q5双线性224×64采样的颜色隔离对照：388张正图的392候选颜色通过全部一致，1164残缺帧有1个原本已拒候选的颜色通过转为拒绝，所有最终选择均不变。结果见`color-sampling-comparison/`。

据此可优先评估在已有224×64整数RGB输出上累计蓝黄计数，避免为颜色统计新增原生尺寸图像缓存。此对照固定了原识别概率、颜色CNN类别和其他门控，**没有验证把固定图重新送入全部模型后的端到端等价**。颜色计数本身也不相等；继续改变采样尺寸、插值或裁剪范围仍需对照。

原1552帧记录共有1565个可采样候选，观测到的最大原生输出为304×101、30704像素，容纳这组观测计数需要15位；这不是通用尺寸上限，101行也不能直接套用320×96读取请求。统计见`color-candidate-confirmation/observed-crop-bounds.json`。资源评估沿用主控保留模块后的39 DSP/73 RAM剩余额度，不把裸视频后的43 DSP上限当可用额度。

已有`locator/rtl/blue_hs_filter.v`验证的是蓝色谓词，可作为资源分析参考；黄色谓词、这两个计数器和最终组合尚无RTL或map结果。不把算法级“只需计数”写成已综合的LUT/RAM/DSP数字。BGR软件通道顺序与硬件RGB打包须显式对应。

同一冻结320检测器在388张正图重新统计：每帧6300条原始预测，objectness>.25后、NMS前为6—12条（中位数9，P99为12），NMS后384帧1条、4帧2条。原NMS后角点及检测分数完全重现。统计在`detector-candidate-counts/`；没有截断，也不能将观测最大12当作所有场景的缓存上限。

## 极值和能力边界

4×4合成块的固定测试：灰色0/0拒绝；纯黄S=254为0/16拒绝；纯蓝S=254为16/0通过；纯蓝S=255因严格排除255而为0/0拒绝；蓝黄各8像素时拒绝。这些结果保留，不为饱和纯蓝或已见偏色样本修改条件。

只有1个有效蓝像素、其余灰色时，颜色规则为1/0并通过。它没有最低蓝色面积约束，因此仅提供颜色一致性证据，**不是车牌存在、字符数量、字符完整性或可靠识别的证明**。其余检测、格式、置信、边界和帧时效规则仍必需。

开发中额外拒绝的76、112及校准新增拒绝的57按实测损失保留，不加例外；真实绿牌、真实物体遮挡交通全帧和大量复杂道路无牌图仍须另外验证。本文件供模型与资源工作直接读取，未触发跨聊天消息或硬件集成。
