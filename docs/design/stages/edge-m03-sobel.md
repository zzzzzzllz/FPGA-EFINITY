## 算法与接口

- 输入为 M02 的完整 1280×720 RGBY，沿用 50MHz 双像素，字高位像素在前。M03 采用两个并行 Sobel 运算通路，不引入 100MHz 跨域解包。摄像头、曝光及 HDMI 720p60 配置保持原值；加载脚本采用用户在高帧率试验恢复后确认的新白平衡 389/256/427。
- `sobel_pair.v` 用一行 64 位 RGBY 缓存和一行 16 位双灰度缓存形成三行窗口，RGB 随中心像素延迟，输出位置不偏移。
- 任务书核为 `Gx=[[-1,0,1],[-2,0,2],[-1,0,1]]`、`Gy=[[-1,-2,-1],[0,0,0],[1,2,1]]`。梯度使用 11 位有符号数，范围 −1020～1020；绝对值与和保留 11 位，不截成 8 位。
- 二值判定严格为 `abs(Gx)+abs(Gy)>32`，相等为黑色。32 是当前固定工程参数（前两版为128、64），并通过 JTAG 只读状态返回；板载调节留给 M05。
- 窗口复制四边，最终最外圈一像素强制为黑色。每帧仍输出 921,600 像素，黑底白边为 0／255。
- `valid && ready` 时推进状态；输出受阻时连同帧标记一起保持。每行最后一个输入双像素后需要一个尾处理周期，末帧另需 640 个补行读周期及一个尾周期。实际摄像头在这些位置有消隐，顶层不反压摄像头；`sobel_overrun_cycles` 明确记录不可接收期间仍有有效输入的周期数。
- SOF 对应 `(0,0)` 的像素对，EOL 对应每行 `(1278,1279)`，EOF 对应最后一行最后一对。帧号和参数版本在输入 SOF 锁定，直到补齐末行都保持这一帧的元数据。`processed_frames` 现在统计 Sobel 输出 EOF。
- DDR 写帧同步由输入 SOF 拉低、Sobel 输出 EOF 后拉高，给首行缓存预热和帧缓存 FIFO 复位留出时间，也保证末行写完再结束帧。

## 数据与使用方式

DDR 每像素仍为 32 位，格式从 M02 的 `{Y,R,G,B}` 改为 `{E,R,G,B}`。RGB 逐位保留，灰度显示复用相同的 `(77R+150G+29B+128)>>8` 公式恢复 Y。三个视图均经过同一周期延迟，HDMI 同步／有效信号一起延迟。

```bat
test-edge.cmd
build-edge.cmd
load-edge.cmd
camera-control.cmd --edge --view edge
camera-control.cmd --edge --view gray
camera-control.cmd --edge --view color
camera-control.cmd --edge --samples 5
```

构建标识为 `0x60101003`，加载后默认边缘视图。模式在 HDMI 垂直消隐提交，命令保留当前白平衡。调试 profile 更新后仍用 `D:\Efinity\bin\python3.bat tools\generate-edge-debug.py` 生成 RTL。
