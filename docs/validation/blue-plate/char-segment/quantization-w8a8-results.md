## 范围与冻结

沿用原68类预训练网络、blank67、batch1及冻结Q8 BGR输入。只用已有207个复核train ROI统计FP32 min/max，先冻结量化参数，再评价307个development ROI、304个身份；76tune是其中子集。零优化器步骤，模型状态不变，未按评价结果调尺度或门限。本轮84校准图、112heldout图片读取均为0。

[实施前方案](quantization-plan.md)记录实际阅读的LiteRT、CMSIS-NN与PyTorch实现；本候选使用逐输出通道W8、逐张量非对称A8、int32累加及最近偶数舍入。[整数接口与MAC向量契约](integer-mac-contract.md)给出运行时整数算术、位宽、布局和向量用法。网络之后的log-softmax与精确CTC概率仍由主机浮点计算，接受链属于混合精度诊断。

## 损失定位

逐层相对RMSE定义为 `sqrt(sum((integer_dequant−FP32)^2)/sum(FP32^2))`，汇总全部307 ROI，不先平均各图百分比。

| 融合层/节点 | 相对RMSE |
|---|---:|
| 首卷积 backbone.0 | 1.2231% |
| backbone.4.block.6（tap1） | 5.3888% |
| backbone.8.block.6 | 3.5344% |
| backbone.11.block.6（tap2） | 2.5918% |
| backbone.14（通道抽取后） | **32.8672%** |
| backbone.16 | 38.7979% |
| backbone.20（tap3） | 31.3147% |
| 四支归一化 context.0 / 1 / 2 / 3 | 3.1530% / 8.1585% / 10.4964% / 29.6038% |
| concat | 18.1912% |
| container.0 | 7.5840% |
| 高度均值后 logits | 6.9059% |

logits平均绝对误差1.45443，最大50.33338。所有29个节点的误差、整数范围与逐图记录见 `layer-summary.json` 和 `roi-layer-errors.json`。

关键损失发生在最后一次通道抽取。tap2的207train范围上限为300.160034，A8步长1.177098173；之后空间最大池化并每4通道抽取一通道，保留通道的FP32标定上限仅8.3100605，却仍使用该步长。全部307的抽取输出只出现 `[-128,-121]`，即8个整数值、7个间隔。大幅值通道影响了全张量尺度，却未进入这条后续主干。tap2同时送入上下文支路，因此简单整体缩小其尺度会影响另一消费者。

按事先冻结规则只追加两项定位诊断，不另找尺度或门限：

| 同一严格门限，OCR | 304dev | 同76 |
|---|---:|---:|
| 全FP32 | 250／0／54 | 61／0／15 |
| 整数主干 + FP32上下文/输出层 | 234／3／67 | 56／0／20 |
| FP32主干端点量化 + 固定整数上下文/输出层 | 245／1／58 | 58／0／18 |
| 本轮整数主干/上下文/输出层 | 229／3／72 | 55／0／21 |

恢复浮点主干带来的改善明显更大，支持优先处理主干范围分配；第二项仍将四个端点按既有A8尺度量化，并不是无损主干接口。两项结果不能相减当作各模块独立贡献。

共418,453,280个被统计的卷积/上下文输出中345个发生越界饱和，其中207标定ROI内13个，其余100 ROI内332个。首层252个均来自标定集外；上下文支路1/2分别32/18个。相比普遍的抽取后低分辨率，稀疏饱和不足以单独解释主干损失。没有据此重调参数。

## 算术验证和下一步边界

- 全部307条FP32 logits与既有冻结输出逐元素相同；三个ROI的BN融合/输入偏置变换最大误差 `4.57763671875e-05`。
- 保存后的整数参数重放精确一致；独立NumPy int64完整首层、四个上下文分支的NumPy窗口和Fraction有理数计算、末高度整数和均精确一致。
- 555项正负与半整数舍入、12项signed8极值矩阵乘检查通过；36个真实点积的4,437个八路周期和末重定标值全部匹配。
- 原权重和模型状态不变，量化参数冻结后不变。参考实现没有动态浮点神经运算；主机CTC仍为浮点。`verification.json`保存核对结果。

下一条有直接证据支持的路线，是在tap2分叉处按消费者分别量化：从未压缩的累加结果保留主干所需通道，再按它们自己的范围生成A8；或先保持较宽激活直到通道抽取结束。**抽取后对现有A8重定标无法恢复已丢失的信息。** 这需要改变分叉的算术/缓存接口，应由主控评估后冻结第二候选；本轮没有实施第二候选，也没有追加训练或84量化确认。

[GreenWaves实物实现对比](greenwaves-quantization-comparison.md)已读取厂商核心脚本、C入口和实际TFLite模型。其71类、88时间步、FC/sigmoid上下文结构不同于当前68类网络，不能将其量化部署结果视为本网络通过。

完整性问题另有独立失败证据：主实现 `tmp/blue-plate-normal-g1/mature-detector/lpr-rejection/report.json` 与 `strict-failures.json` 记录，中部20像素全帧遮挡在原FP32严格链下错误接受66/388，最高分0.99999097；四种颜色组合均未消除。这轮没有重跑遮挡集，量化后分数变化不构成完整性修复。完整网络仍不可部署。
