# 可读性与可见性：有界源码调研及首版边界

本轮找到并实际阅读了 LPLC、LPLCv2 两代公开可读性分类实现。它们能把图像质量判断从 OCR 文本分数中分离，但**没有找到可直接用于普通蓝牌七字完整可见性拒识、且适合当前 Ti60 资源与服务时间的现成实现**。两者属于同一研究路线，不能算两项独立验证。用户现已确认首轮验收受控机位下清晰完整无遮挡的单个普通蓝牌，遮挡拒识留作后续改进。当前不增加模型或训练；首轮接口与整链接入继续推进，未验证量化模型和板卡烧录仍未放行。

## 1. LPLC：有拒绝类别，没有逐字可见性输出

[论文的标注定义](https://arxiv.org/html/2508.18425v1)区分四级可读性与牌面遮挡。四级从不可读、差、良好到清晰；遮挡另有布尔属性。论文明确允许部分字符被遮挡的车牌仍有 OCR 文本标注，因此“有号码真值”不能转成“每个字完整可见”。论文早期版本与仓库的统计及遮挡字段极性表述存在差异，本轮未取得原始标注，不据此生成训练标签。

实际代码链条是：`gen_splits.class_mapping/load_fnames` 将可读性目录合并为分类目录；`LPSD_Dataset` 从父目录名读整数标签；训练将整张牌面送入分类网络；`eval_model`/`predict_torch_model` 取最大 logit 的类别。没有读取逐字可见性、遮挡掩码或字符位置标签，没有可见性输出头。

四类配置保留原四级；三类配置合并 good/perfect 为 legible，同时保留 poor/illegible。二类配置之一只比较 poor 与 good/perfect，排除 illegible，不能误用成全输入的拒识验证。网络可以输出应拒绝的低质量类别，但源码没有本项目要求的严格完整性接受阈值或校准协议。

Torch 训练默认配置名为 `focal`，实际调用的是带类别权重的 `CrossEntropyLoss`，没有 focal 的调制项；YOLO 分支交给 Ultralytics，已核对其分类损失为普通交叉熵。两条路径都在预测可读性类别，不是补全文字，也不是证明遮挡不存在。

输入细节也不能直接沿用现 LPR：Torch 数据读取为 OpenCV BGR，超尺寸时按比例 INTER_AREA 缩小、小图不放大，居中填充 127，随后 ToTensor；所检查小 CNN 配置为 64×192。YAML 版末尾带 Softmax，Python 类版输出 logits，二者不是可以忽略差别的同一训练入口。

## 2. LPLCv2：改进分类训练，监督目标仍是可读性

[新版论文](https://arxiv.org/html/2604.08741v1)增加摄像头、采集条件和车辆属性，提供跨摄像头评价；列出的遮挡属性是车辆层级。可借鉴的是将采集来源分开评价，而不是把同摄像头近似图随机分组后当作独立泛化证据。

实际默认配置为 ResNet-50、90×180 输入、四类头。`LPSD_Dataset` 仍从分类目录读标签；`trainer.py` 选择交叉熵、加权交叉熵、真正的 focal，或 `FocalEMA`。后者以当前分类混淆矩阵更新 EMA，再计算按类加权的负对数似然；它没有遮挡或逐字可见性损失。这里的 EMA 是训练中的统计量，**不是部署时的多帧追踪或投票**。预测仍取最大 logit 类别。

`transforms.py` 有额外变换定义，但当前 `LPSD_Dataset` 的实际取样路径使用 `resize_with_pad` 与 ToTensor；不能仅看到变换文件就声称增强已进入训练。代码目标确实支持拒绝低质量牌面，但本轮没有可用权重及中国蓝牌验证，不能把论文指标当成本项目完整性指标。

## 规模、算子与 Ti60 适配

`architecture-sizing.json` 保存独立规模核算。小 CNN 按已读层定义直接计算；ResNet-50 用本机官方 torchvision 0.26.0、`weights=None,num_classes=4` 实例化后计数，未加载权重、未推理、未训练。下列 INT8 大小只是参数数目乘一字节的理论值，不代表已有量化模型，也未计运行缓存和量化元数据。

| 路径 | 规模与主要算子 | 对当前工程的判断 |
|---|---|---|
| LPLC Python 小 CNN，64×192，四类 | 3,151,556 参数，理论约3.15 MB INT8；22,610,432 MAC；两层3×3卷积、池化、BN、ReLU、两层全连接 | 算子较简单，但大部分参数落在全连接层，必须额外安排权重搬运；8路100 MHz纯MAC下界再加28.26304 ms/ROI。不是现颜色CNN的免费附加输出 |
| LPLC YOLO11n-cls 配置 | 已读源码含卷积/BN/SiLU、C3k2、C2PSA注意力矩阵乘与softmax、全局平均池化、全连接 | 不能按普通小卷积分类器估计；源码注释的通用模型规模未核成该任务四类权重，本轮不报适配后MAC数、不建议接入 |
| LPLCv2 默认 ResNet-50 四类 | 23,516,228 参数，理论约23.52 MB INT8；卷积/BN/ReLU、残差加法、池化、全连接 | 需明显增加权重/激活流量与计算；没有理由在现资源和时限尚未闭合时再加这一网络 |

现保留模块后的预算为39 DSP、73 RAM；现三模型8路100 MHz纯MAC下界已为单ROI416.13772 ms、双ROI602.49944 ms。这些下界不含DDR、几何和调度。小CNN即便能复用计算阵列，也会占服务时间和DDR，不能据“只增加一个头”宣布可部署。完整链实测时间仍未知。

两 LPLC 仓库所查树中没有独立 LICENSE、任务权重文件；LPLC Releases 为空，唯一开放 Issue 为数据公开发布请求。数据需申请，且限定申请人学术使用。应称为**公开源码研究实现，复用授权尚未明确**，不能直接声称已有可自由部署的开源组件。Ultralytics 已下载许可证为 AGPL-3.0。本轮没有联系作者或申请数据。

另查到 [SAVH 可读性研究](https://www.preprints.org/manuscript/202607.1926)：它明确区分相机OCR与YOLOv8n-CLS质量分类，但正文/数据入口未定位到项目训练和推理源代码；[Zenodo条目](https://zenodo.org/records/21120307)列的是两个图像压缩包。故没有把它算成第二个经过源码验证的实现，也没有下载图像。

## 首版场景与已知边界：供主控决策

下面按用户已确认的首轮范围整理现有证据。首轮检查彩色视频连续、七位真实号码、来源与过期清除；表中证据不等于已经板上验收。

| 场景 | 现有证据 | 首版处理建议 |
|---|---|---|
| 单个、完整无遮挡、清晰普通蓝牌；受控机位、静止或低速 | 冻结结构链已见388正图292正确/0错/96拒；84校准为64/0/20，非独立盲测 | 用户已选定首轮场景；记录实际尺度、角度与时延，31省全覆盖不额外列为首轮必过项 |
| 左/右裁切、中部整段字符缺失 | 既有1164合成残缺全部拒绝 | 保留为后续遮挡质量回归，不能推广成任意遮挡均拒绝 |
| 窄条或水平遮挡，残留笔画似另一合法字 | 新16探针4接受，其中3错文；一例教师和LPRNet同错 | 已知失败，归入后续遮挡改进；多帧或双模型一致不能证明遮挡已解决 |
| 真实黄牌及已有非牌诊断 | 现107条真实诊断组合均拒绝；含96patch、11全景，107条仅106唯一图 | 作为有限负例；patch不能冒充全景检测证据 |
| 自然复杂遮挡、真实绿牌、大规模独立道路无牌、极端模糊/反光 | 尚缺匹配的独立验证 | 不纳入已通过范围；如作为首版硬要求，需要新增明确标注和评估授权 |
| 多候选、快速驶过、连续更新 | 两候选仅纯MAC下界已超过现500 ms | 必须整链测来源年龄与更新间隔，不能以离线识别正确代替实时验收 |

用户已选择受控首轮，不再等待范围回复，也不为后续遮挡目标新增模型、追踪、训练或对16例打补丁。已有失败证据保留；后续若启动遮挡改进，再明确独立可见性标注及评价授权。

## 最小显示契约备选，仅文档建议

沿用[显示契约修正建议](../../design/blue-plate-display-revision-proposal.md)：一次通过首轮冻结接受条件的结果可在帧边界提交；保留原始来源时间和身份，新来源优先，晚到旧包忽略；较新拒识/无目标/错误清空；显示域独立检查来源年龄，到期清空。实时彩色视频继续运行，不用旧号码掩盖更新空窗，不加历史或追踪。

“三次一致”和“500 ms”在现需求记录中是待验证内部参数。应以实际来源到提交延迟、来源间隔和允许新鲜度确定期限D：首次显示要求 `L+V<D`；无空窗更新还要求后继提交早于上一来源到期。单次策略只减少等待次数，不能解决遮挡误接受或让已过期任务有效。

**有界调研已完成，通用遮挡拒识不再作为受控首轮的前置条件。** 当前继续独立RGB接口和整链准备；单次确认及TTL须按实际时延冻结，未验证量化模型、共享顶层、release与板卡不因范围决定而自动获准修改。后续可见性改进应独立统计遮挡误接受、正常牌保留率及计算代价。
