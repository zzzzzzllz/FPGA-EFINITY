# 固定LPRNet完整拒识链复验

新LPRNet严格门限仍错误接受66/388张中间遮挡全帧，当前不具备完整文字拒识能力，不能据此放行可信显示或整机识别。左右边缘残缺388+388帧和107条已见真实诊断记录全部拒绝；该结果保留了颜色和边界门控的作用，但不抵消中间遮挡失败。

## 固定链和验证

调用模型窗口交付的[固定推理入口](char-segment/fixed-lprnet-contract.md)：320检测器→现有Q32/Q5彩色224×64→现有Q8 BGR24×94→原公开LPRNet、68类、blank67、CPU batch1。严格门限固定为0.9931710550839266，0.9386077887914179只作对照；没有拟合新门限或回退放行。实际读取[原网络](https://github.com/sirius-ai/LPRNet_Pytorch/blob/master/model/LPRNet.py)与[数据变换实现](https://github.com/sirius-ai/LPRNet_Pytorch/blob/master/data/load_data.py)，本地固定副本及权重在`tmp/blue-plate-review/mature-research/lprnet/`，由入口校验SHA256。

1,164张既有残缺全帧重新检测，另外107条真实输入包含96条patch和11张完整场景。共1271个输入、1277个ROI；patch使用其自身四个外侧像素角点映射到224×64，仅作下游诊断，没有全帧检测或画面边界判定。112张heldout未读。32/2独立数量检查在1175张全帧上均未溢出，NMS沿用原实现。

每个ROI实际运行新OCR，无论旧OCR是否拒绝；不使用HyperOCR .9/.8、旧接受标志或旧拒绝原因。单独记录七字合法性/CTC分数、原始四角和框边界、学习型蓝类、HS蓝大于黄。各条件通过后按新CTC分数选牌，同分取较小候选索引。

颜色分类分别实际推理“原生可变尺寸crop→96×96”和“Q32/Q5 224×64→96×96”；两者使用同一原始分类器编码及OpenCV线性resize。HS也分别计数，构成四种CNN/HS输入组合。没有默认类别相同。

## 失败根因证据

严格门限66例中，56例来自development、10例来自原validation划分；全部输出均与原无遮挡文字不同，分数范围0.9936828805263833—0.9999909704094386。原文字仅用于本项错误核对，没有挂为残缺图训练标签或参与选牌。

已查看最高分等代表性224×64裁剪，中央字符确实被实色条遮掉。例如sample243输出“皖A1L391”、分数0.9999909704094386，sample75输出“皖AFL300”、分数0.9999306344820845。输出合法且概率高，不能证明每个字符有可见图像支持。边界门控只查画面内位置，颜色门控只查牌色，因此无法识别牌内的遮挡。

![严格门限仍接受的遮挡ROI](../../../tmp/blue-plate-normal-g1/mature-detector/lpr-rejection/accepted-roi-553.png)

逐ROI新logits的独立NumPy CTC动态规划与入口分数核对，最大log概率差1.78×10⁻¹⁵；12710个选牌结果独立重建一致，模型参数/缓冲区及输入源码哈希未变。1277个原生颜色类别和全帧几何字段也与旧检测记录一致。这些证据排除了候选错配、误用旧门控、CTC计算错误和颜色采样类别变化作为本次66例的解释。

本轮不通过抬高置信门限补救：最高错误分数已接近1，而且主控要求冻结门限。后续合理方向是独立验证文字可见性/完整性证据，或选择在遮挡拒识上表现更可靠且能满足资源预算的识别后端；应先研究成熟实现并做同一冻结诊断，不直接增加未经验证的RTL。三帧一致对持续遮挡的同一系统性误识没有必然保护，不能用显示策略替代本项修复。

## 颜色采样结论

1277个ROI的学习型类别变化为0；分类分数平均绝对差0.00024636，最大0.14415050，因此不能称概率完全一致。HS通过变化1例：sample419右边缘残缺第二候选原生蓝/黄2/0，固定0/0；新OCR为非法短串“苏40AJ”，两种均拒绝。两固定门限下，四种CNN/HS组合逐输入选择均完全相同。

该结果支持这批拒识输入使用固定224×64颜色输入，但不替代388张完整正图上的颜色CNN采样对照；此前完整正图只验证过HS采样变化。模型窗口的68/0/16校准正图结果沿用原生颜色记录，不能直接冠以固定颜色CNN的成绩。
