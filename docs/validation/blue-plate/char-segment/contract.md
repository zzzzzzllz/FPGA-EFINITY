实测：队列占用峰值113，全部组件数最多113，符合前置字符条件的组件最多10，清理后前景最多6479。详见 `tmp/blue-plate-char-segment/resource-audit.json`、`reference.json`、`reference.npz`。这批NPZ中的RGB是冻结OpenCV参考采样，不能把它误称为整数几何逐像素输出；随后集成仍需以perspective_roi实际灰度验证。

## 算法顺序：不改变语义

1. `(gray>>3)>plate_threshold`，先清y=0..4/59..63、x=0..3/220..223。逐行统计223对相邻像素跳变和224像素行和；跳变<8或行和>190整行清零。
2. 在清行后的掩膜计算8连通组件。h<12删除。右边框候选条件是x≥210且w≤10；前置组件必须满足a+c≤x、h≥23、3≤w≤36，按完整(x,y,w,h)元组排序，取最后六项。统计取自本阶段原始所有组件，不因先删除其他边框而变化。
3. 使用两倍中心C=2x+w。六中心的五个差中跳过第一个，排序剩余四个D；令P4=D[1]+D[2]。原条件精确等价为68≤P4≤152且 `8*(C_rim-C_last)<3*P4`。比较严格小于，保留窄末字和正常间距保护。
4. 清理后的列和用于六个中心34/70/101/132/163/194，各搜索中心±9，按(列和、离中心距离、x)最小选择；最小列和>8立即拒绝。边界固定4和220，不均分补框。
5. 各区间[left,right)求前景bbox。必须非空且 `max_y-min_y>=23`，故实际框高至少24；宽≤36。保留baseline随后冗余的h≥23检查，不把实际下界误写为23。
6. 每框从未清理的原始灰度取 `[max(0,y-2):min(64,y+h+2),x:x+w]`，重新统计32档直方图并调用已审核otsu32。任一单档/无效字符拒绝整牌。**七个阈值全部成功后才输出任何字符**，以免后一个失败时前几个已经被当作完整结果消费。
7. 按位置0..6逐行输出原始二值ROI，只做阈值比较。已有char_preprocess随后归一化一次；切分核不归一化、不提取分类特征。

## 存储与连通域取舍

选择固定512项像素BFS队列和两个1位掩膜。入队时立即清visited位，同一遍每像素最多入队一次；读改写串行，杜绝相邻像素重复入队。队列满时整牌返回overflow，不能截断队列继续正常输出。

- A保存行清理后的工作掩膜；B初始化为A，用作遍历时可清零的visited图。
- 第一遍遍历B，得到所有组件统计，收集h≥23且3≤w≤36的bbox。h<12组件从同一种子再遍历A并清除。
- 把A再复制到B。仅从右侧x=210..219区域扫描种子，遍历B得到可能的边框完整bbox；扩展仍可访问整幅掩膜，不截断跨过x=210的组件。按第一遍保存的统计判断rim，需删除时再次遍历A清除。这样不用保存整幅像素标签，也不需要保存每个组件的全部像素。
- 前置bbox表512项是可证明的容量：清行后前景≤54×190=10260；每个h≥23组件至少23个像素，因此此表≤446项。512容量检查仍保留，用来暴露实现错误。表中保留可能被随后删除的rim，保持软件统计时序。
- BFS512项不是对任意图像的数学上界；656候选峰值113。复杂合成图若超过512明确拒绝，不承诺所有二值图都能完成。测试将用缩小队列的参数实例强制覆盖overflow路径；生产容量固定512。

与其他方案比较：全图10位标签约143360bit并仍需合并表；保存全部RLE段最坏可达54×108=5832段；流式行标签/回收方案省存储但还须恢复被删除组件的像素，本任务仍需工作掩膜。当前固定小ROI、不要求一像素一拍，优先采用可直接逐组件验证的BFS和必要重遍历。

|---|---:|---:|
| A/B二值掩膜 | 各16384×1，使用14336地址 | 4 |
| BFS队列 | 512×14坐标 | 1 |
| 前置bbox表 | 512×28，x8/y6/w8/h6 | 2 |
| 列和 | 256×7 | 1 |

另有64位行保留标志、七个bbox和七个阈值、六个候选bbox及排序寄存器。主控审核目标：切分核含Otsu≤12 RAM10、0 DSP；实际map报告为准。逻辑使用以实际map对系统剩余预算核算，不按位数换算XLR。若超出本分配，先报告并优化本核，不修改总204RAM/128DSP/49248XLR上限。

## 外部灰度RAM与所有权

**切分核不实例化224×64灰度缓存。** 主实现用唯一灰度RAM接 `perspective_roi.gray_write/gray_address/gray_data`；采样写入完成且结果status=0后，把同一缓存交给切分读取。每个任务期间灰度不可覆盖，直到切分完成握手或abort完成。14KiB按2048/1024深度实际布局交由主实现map，不能在两个模块各放一份。

建议端口（全部同一100MHz域）：

| 端口 | 语义 |
|---|---|
| `start_valid/start_ready` | 锁存`plate_threshold[4:0]`及`plate_status[2:0]`；只接受一项任务，非0整牌状态明确失败 |
| `gray_read, gray_address[13:0]` 输出 | 地址y×224+x，0..14335；固定同步读，无反压 |
| `gray_data[7:0]` 输入 | 主实现模板`if(gray_read) gray_q <= gray_mem[gray_address]`；核在下一时钟的消费状态使用gray_q，不在发起读同拍使用旧值 |
| `char_valid/char_ready` | 一字开始包，`char_position[2:0], char_width[8:0], char_height[6:0]`；宽高为y扩边后的原始ROI，适配char_preprocess.start接口 |
| `pixel_valid/pixel_ready, pixel_data, pixel_last` | 从左到右、从上到下，准确width×height拍，最后一像素last=1；反压时数据/last稳定 |
| `done_valid/done_ready, done_status[2:0]` | 0成功，1上游阈值无效，2队列/统计overflow，3无合格谷值，4非法字符框，5字符Otsu无效，6内部工作量越界；7保留。结果握手前保持稳定 |
| `rst, abort` | 优先于所有握手，立即屏蔽读/字符/pixel/done输出，下一拍回idle；清控制有效位，不清RAM。取消不另产生正常done |

frame_id/epoch/generation/held slot继续由单任务主调度持有，不在小核重复保存。核不直接访问DDR或释放帧。成功done表示七个原始字符的最后输入已被接受，不代表前处理/分类完成；主调度须继续等分类和结果收束再释放held引用。

如果abort发生在已发送部分字符之后，主调度必须同时取消/复位下游char_preprocess和分类事务，丢弃旧结果。下游不复位时，任何切分接口都无法撤回已经握手的像素。外部同步RAM最后一次返回可在abort后出现，核因状态/有效位清零忽略它；灰度所有权回收不涉及DDR排空，DDR排空仍由主读核负责。

## 同步RAM调度与周期预算

所有掩膜、队列、bbox、投影、直方图按同步读推断，不在复位循环清RAM。阶段间显式READ/USE/WRITE，入队先标记visited后才允许查询下一邻居，避免同址读写语义依赖。开始时完整写入随后会读的A/B范围；投影/直方图逐地址初始化。

以N≤10260个行清理后前景计：首次遍历N；删除小组件Nsmall；右侧复查≤N−Nsmall；删rim≤N−Nsmall。因此所有洪泛访问合计≤3N。每入队像素为八邻域同步读改写、队列弹出和统计预留64拍，≤1,969,920拍。右边框候选h≥12且完全位于10×54区域，数量≤45；每候选查512统计记录并维护六项排序，按10拍/项预留230400拍。

清图/复制/扫描/列和/七bbox、灰度两次读取与七次Otsu合计预算保守留约0.8M拍，总内部计算上界先定 **3,000,000拍（100MHz下30ms）**，实现时逐FSM重新核算并由仿真周期计数验证。已有otsu32六次移位乘法的操作数位宽上界15/15/35/15/30/30，31个候选阈值加加载/比较预算每字≤5000拍。

该上界不包含下游字符启动和像素反压的等待；任意外部永久反压本来没有有限壁钟上界。系统任务超时通过abort收束，不能为了限定时延丢弃像素。首版内部进度看门限也不应把正常等待算成算法超限。
