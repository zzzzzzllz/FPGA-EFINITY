# 成熟整牌路线：拒识诊断

## 已确认的问题

HyperLPR 320检测+整牌识别在原388张图片上得到387正确、1错，证明新路线能解决大量原定位/切分失败。但普通七位格式、蓝牌类别和平均字符概率不能证明输入文字完整。以下实验用于找到拒识缺口，不计入G1，也不与独立无牌场景混算。

原比较和固定采样报告保持不变。112张heldout未读取。所有合成变体按原图继承development/validation划分；验证变体只用于评测，不能进入训练或量化校准。

## 全帧对应测试协议

脚本：`tools/blue_plate/probe_hyperlpr_fullframe.py`。独立目录`mature-detector/fullframe-rejection/`，存在时拒绝覆盖。`protocol.json`在推理前保存。

每张原图生成未改动、左边缘裁切、右边缘裁切、中间遮挡四种全帧输入。原最高检测置信度四角只用于定义干预位置：左右截线取两侧中点连线20%/80%的x坐标，以整数平移把截线移到画面边缘，原像素尺度不变，另一侧补零；中间遮挡用四角单应性将归一化40%—60%竖条投影回原帧。斜牌的边缘截切不等同于严格裁掉每一行20%。

每个变体重新检测、按新四角矫正、识别和判颜色。任一单层候选通过即记该帧接受，不用标注选择候选。预设门控逐层比较：格式+蓝类、再加均值≥.9、再加全部原始浮点四角距图边≥1像素、再加检测框距图边≥1像素。角点检查在转整数和采样前进行，避免越界被截断隐藏。

依据是已读取的[HyperLPR原始裁剪实现](https://github.com/szad670401/HyperLPR/blob/9307450f7b7915be18f23a539ec05b41fe6629f4/Prj-Python/hyperlpr3/common/tools_process.py)：`get_rotate_crop_image`使用`BORDER_REPLICATE`，未在此函数中拒绝越界四角。门控只检验画面边界证据，不把角点位于图内当成文字完整的充分条件。

所有错误接受全帧及裁剪保存；原字符串仅作原图参考，变体`training_text_label=null`。开发失败标为待复核拒识候选，验证失败仅评测。

## 蓝黄颜色证据的开发诊断

在上述真实失败出现后，经主控要求继续研究最小补充规则。原冻结参考、.8门控、原始报告均保持不变；本节是已见失败数据上的开发诊断，不是新的独立测试。

已实际下载并读取EasyPR固定提交的`src/core/core_func.cpp`第10—138行`colorMatch`、286—301行`plateColorJudge`、304—333行`getPlateType`；源码SHA256为`8e72c252c8e873b7a2f7a4531db6036751a48b039397dfddd0dc560ee9e8a9ea`，保存在`mature-detector/easypr-judge/`，链接：[原始源码](https://github.com/liuruoze/EasyPR/blob/a0a9f3c3f612e7c8d9046bd9c5770249cfb86850/src/core/core_func.cpp#L286)。

实际实现使用OpenCV HSV，先均衡ROI的V通道；蓝色为100<H<140，黄色为15<H<40。固定模式要求95<S,V<255，自适应模式根据H到范围中心的距离将S/V下限设为约32—64。`plateColorJudge`要求匹配像素比例严格大于.45。需保留源码整数除法细节：黄色半宽为12、中心27。`getPlateType`在各颜色均不满足时默认返回BLUE，这个兜底不适用于可信拒识，本轮没有采用。

`diagnose_color_evidence.py`统一比较三种事先写入协议的规则，没有门限拟合或扫参：

1. 原固定S/V模式，蓝色覆盖率>.45。
2. 原自适应S/V模式，蓝色覆盖率>.45。
3. 明确标注为适配的简化规则：沿用同一蓝/黄色相范围及95<S<255，省掉V均衡/门限，仅要求**蓝色像素数>黄色像素数**。两者均为0时拒绝，不沿用“未知当蓝色”。

第三条不是EasyPR已经采用的规则。它取其像素颜色证据并适配为现有识别/颜色分类之后的附加拒识条件，无新网络、学习参数或按号码例外。逐候选统一应用后再按原置信顺序选结果；不能只检查原胜出候选而漏掉候选切换。向量化端口已与逐像素源代码顺序的标量谓词对照，验证蓝/黄色界限、严格比较与自适应计算。
