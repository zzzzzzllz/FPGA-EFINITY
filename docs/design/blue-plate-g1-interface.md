# 蓝牌 G1：帧接口与资源约束

2026-10-18。本文冻结任务边界和接口语义。视频底座、字符前处理/分类、显示及Otsu已有独立实现/验证；完整定位、几何采样、切分与共享顶层尚未闭环。算法最新比较见 [真实数据记录](../validation/blue-plate/normal-data-candidate.md)，G1尚未通过。

## 构建与视频路径

保留 `coding/edge-quality-30fps` 和其 release。车牌候选采用共享源码、独立顶层配置、独立 `tmp/build/blue-plate-<标识>/`；不能把工程名继续设为 `edge-quality-30fps` 后调用会删除该目录的 `tools/build-project.ps1`。

车牌构建在综合时关闭 Canny、形状识别和车牌模式不用的历史操作，保留相机、图像处理、DDR、实时彩色显示。现有 `frame_store` 的作业完成参与结果发布，不能把识别耗时直接延长到它的 `job_done`，否则识别会拖慢实时画面。识别建立独立帧引用与读请求，视频发布按原路径完成。

当前 raw slot 地址为 `slot * 0x300000 + four_pixel_offset * 12`；1280×720 RGB24 实际占2,764,800字节。DMA 的128位总线经过3相位拆包恢复四个RGB像素，算法侧再按两个像素处理。不能将一个总线拍直接解释为固定两个像素，ROI首尾和跨行须由同一拆包器处理。

## 单任务契约

核心时钟100MHz，图像坐标用原始720p坐标。每次最多持有一个来源帧；接收任务时原子锁存全部字段。

| 接口 | 字段与语义 |
|---|---|
| 任务 `job_valid/job_ready` | `slot[5:0]`、`frame_id[31:0]`、`epoch[31:0]`、`generation[31:0]`、`source_time_ms[31:0]`；只接收已完成且有效的raw帧；源时间取采集开始时的核心毫秒计数 |
| 帧持有 | 接收任务同周期将该slot加入`frame_store_control.held`；定位、阈值统计、ROI及字符读取一直引用该slot |
| ROI读命令 `req_valid/req_ready` | `x[10:0], y[9:0], width[8:0], height[6:0]`；定位全图扫描使用单独操作码，不把宽度1280塞入9位ROI宽度 |
| 像素响应 `pixel_valid/pixel_ready` | `rgb0[23:0], rgb1[23:0], keep[1:0], x[10:0], y[9:0], line_last, frame_last`；坐标对应第一个像素；奇数宽尾拍由keep指明 |
| 结束 `done_valid` | `frame_id, generation, status`；正常、无候选、切分失败、字符拒识、超时、总线错误都走结束路径 |
| 释放 | 没有未完成DDR事务或已排空响应后释放一次；超时不允许把尚在写FIFO的旧事务数据混进下一任务 |

相机入口不接识别反压。识别忙时拒绝新识别任务并增加跳帧计数，采集和HDMI仍运行。DDR在突发边界仲裁：采集写和显示读保留期限保障，识别只使用剩余带宽；识别读返回进入有空间保证的FIFO，未预留整突发空间时不发读请求。不能在AXI响应中途无限停顿并占住显示通道。

复位/配置代次变化首先使结果失效。超时触发取消并排空，再释放slot；恢复前不得发新任务。复位清零引用表，DDR重置完成前不接收识别任务。验收需注入复位、读错误、最后一拍丢失和任务超时，检查帧引用无泄漏且视频没有被识别永久占用。

具体读核状态与竞态以已批准的 [frame_reader契约](../validation/blue-plate/frame-reader/contract.md) 为准，包含原子hold、单在途32拍缓存、cmd_last、同帧多ROI、取消排空及recover握手。上表只描述系统语义，不替代该端口定义。

## 七位结果与显示

字符ID取固定65类表，7位编码可容纳65类；`7'h7f`为无效字符。第一位31省，第二位24字母，后五位34英数字。查表顺序须由同一生成器输出Python标签表、ROM与OSD表，不能手工维护两套索引。

结果包至少包含：版本号、来源frame_id/epoch/generation、状态、七个字符ID、七组signed32最佳分数与不同类别分差、原始定位框、任务耗时。当前是整数线性分数，越高越好，不写成概率。普通与严格门限来自冻结的 `char_model/candidate/interface.json`，整牌可靠性尚未通过 G1，不能把离线“accepted”当已完成三帧确认。

同目标关联依据来源帧的框重叠和中心移动，连续三张不同来源帧的七位结果一致才确认；重复同一frame_id不累计。任何拒识/目标跳变/中断重置连续计数。结果有效期以最新支持该号码的来源帧年龄计算，不能靠重复消费旧结果延寿；初始候选500ms，实拍确认后确定。号码过期、目标离开或配置变化时清空。

复用现有 `frame_mailbox` 整包握手。它的 `dst_data` 在握手到达时改变，并不等待HDMI帧边界；目的域必须另存pending包，**只在显示帧开始时原子提交七位、状态和有效性**。首版固定结果栏显示完整中文号码或未识别，不把旧帧定位框叠加在当前视频上。

## 资源门槛与核算

冻结边缘版本为49156/60800 XLR、188/256 RAM、111/160 DSP。保持原预算线：XLR最多49248，RAM最多204，DSP最多128；不能修改余量要求。精简视频底座已独立验证为24090 XLR、106 RAM、85 DSP。早期6000 XLR/28 RAM/8 DSP是模块分配设想，已不足以覆盖当前分类核，需要按此底座重新分配；总上限不变，各核简单相加也不能替代整机PNR。

| 方案 | 原始ROM容量 | 比较工作量 | 当前决定 |
|---|---:|---:|---|
| 65类，每类3个16×32二值模板 | 12,480字节 | 675个模板比较/整牌 | 基线未证明可用，不能直接接RTL |
| 65类，每类最多12个模板 | 最多49,920字节 | 最多2700个比较/整牌 | 仅软件诊断；实际藏字样本不足12个。不能沿用3模板的RAM估算 |
| EasyPR发布的ANN | 以实际模型层数、量化格式重新核算 | 先做相同字符ROI对照 | 小样本对照不足以定型；模型/量化由字符工作窗口继续 |
| 当前320特征×65类整数线性模型 | signed10有效权重及32位偏置共26260字节；软件int16口径41860字节 | 每字20800 MAC，当前核输入后41796拍 | 单一离线主候选；独立map为33 RAM、1 DSP，见字符窗口RTL记录。需按精简底座重新审核模块分配 |

ROI最大320×96二值缓存3840字节，当前七个32×32字符缓存896字节，320项6位特征240字节，65字显示字库4160字节，另加直方图/投影/FIFO/行缓存。32×32输入已经归一化时直接提取特征；原始字符ROI只归一化一次。RAM块数由真实端口、位宽与布局决定，不按总字节除块容量当综合结果。前两种模板仅为历史对照，不并行接入产品。

32档Otsu已实现精确整数有理比较。N≤30720时，累计矩`sum(i*hist[i])`20位，乘积N×矩35位；平方70位，交叉乘积100位。RGB直方图串联核独立map为2 RAM、0 DSP、1772 LUT4、834 FF，真实ROI及极值验证见 [Otsu记录](../validation/blue-plate/otsu-hardware.md)。它提供阈值，尚不包含几何采样、切分或整牌识别。

离线定位仍用了OpenCV轮廓、旋转矩形和透视采样，含浮点运算，不是已证明可用的定点定位器。把它改成投影/定点逐列校正会改变结果，必须重新逐样本验证。此时不承诺6000 XLR能容纳当前软件算法。

## 剩余闭环与下一模块

当前软件主候选为dual-local定位、geometry 11位线性模型、projection-char切分、无额外refinement。388张开发/校准为248正确、6错误、134拒识；112张heldout继续封存。现成MLP比较未改善，不切换分类器。

| 顺序/模块 | 输入→输出契约 | 等价验证与剩余工作 |
|---|---|---|
| 全帧定位 | 同一held帧的720p RGB扫描→最多两个四角候选，附候选来源及失败状态 | 保留HSV/equalize、形态学、连通轮廓、quad/minRect两几何与无候选时local-text。逐阶段比较颜色掩膜、区域、候选坐标/次序；有界CCL若溢出须明确拒绝，不能静默截断后当正常候选 |
| **下一模块：同帧几何采样** | 四角与同一帧读取→224×64 RGB，固定TL/TR/BR/BL和输出扫描次序 | 先冻结全部开发/校准候选的四角、RGB和分数字符；读取OpenCV实际逆映射/插值源码，制定整数坐标、舍入、越界规则，对每个RGB像素、字符掩膜和整牌结果比较。系数求解也必须最终在板上，不接受运行时PC下发矩阵作为完成 |
| 七字切分 | 224×64采样RGB→七个原始二值ROI及宽高/位置，或明确切分失败 | 精确Otsu、外围清零、行跳变清理、8连通域高度/右边框保护、投影谷值、bbox、原灰度字符再Otsu。逐阶段mask、组件统计、六条切线、七ROI逐像素对照；不得把CCL悄悄改成固定切七份 |
| 已验前处理/分类 | 原始二值字符→32×32→320项→65分数/位置受限top2 | 仅归一化一次；geometry权重由分类窗口验证/交付。逐字符ID、分数、分差、门限与冻结向量一致 |
| 调度与显示 | 最多两候选的七字结果→统一候选排序→一次完整结果包 | 保持源frame_id/epoch/generation/source_time_ms；三不同来源帧确认、来源年龄过期、HDMI帧边界原子提交；失败清理并释放一次held引用 |

几何采样先建立与当前OpenCV行为可比较的整数参考和真实候选向量，再实现采样读调度，随后把Otsu、七字切分和已有前处理/分类串起来；定位替换开发并行保留软件对照。所有硬件向量取开发/校准真实图，不因硬件易实现而降级为未经测量的定位。

当前几何链已推进至[四角到同帧灰度/Otsu的完整RTL验证与map](../validation/blue-plate/geometry-hardware.md)：656个真实候选的系数精确一致，完整真实ROI逐灰度像素与阈值一致，尚未接入主定位器或共享DMA。七字切分现由主控交给字符窗口在独占char_segment目录实现；本窗口保留几何、定位及共享集成责任，避免重复修改。

采样存储不能直接放完整RGB 320×96（92160字节）。优先评估frame_reader对同一held帧的按行/小ROI重读、有限行缓存和224×64灰度缓存；选择前测实际读拍数与竞争延迟。先RGB插值再灰度，与先灰度再插值存在舍入差，必须明确验证，不能直接互换。local-text的41行灰度窗口也需采用DDR行重用或实测可容纳的缓存分配。前端各阶段串行运行，可复用明确互斥的工作RAM，但不预先宣称资源能满足。

共享集成由本实现窗口承担。全链先用同帧DDR模型和真实图做端到端对照，再加入采集/HDMI竞争、帧槽复用、错误/取消与复位；通过整机资源/时序后进入SRAM实拍，最后落实复位/I²C默认值与独立上电。

## 2026-10-18路线复核

主控要求深入成熟商用/论文开源实现，基于同样本效果和Ti60成本重新决定路线。当前248正确/6错/134拒识仍为未改善的比较基线，G1未通过；暂停扩大依赖projection-char的新复杂实现。几何生命周期正式回归已经复现主控19任务ROI/16任务quad的通过结果。已在途的[蓝色掩码整数等价检查](../validation/blue-plate/locator-integer.md)也已完成，不把模块测试数量作为识别效果进展。

本窗口正在研究HyperLPR3定位与整牌识别实际源码、官方ONNX模型和同样本表现；主控正在独立研究LPRNet等路线。共享顶层、release、板卡加载保持未改动状态，后续集成以新比较结果为依据。

新增离线颜色候选的模型/资源边界见[蓝底颜色证据候选交接](blue-plate-color-candidate.md)。它保持原FrozenReference不变，只提供逐候选蓝/黄计数的附加拒识条件，尚未接入RTL或批准G1。

固定Q8 LPRNet的[完整拒识链复验](../validation/blue-plate/lpr-rejection.md)发现严格门限仍接受66张中间遮挡图，当前不放行可信显示。另见[显示契约修正建议与首个整链接入清单](blue-plate-display-revision-proposal.md)：三帧/500 ms是旧方案待验证参数；本轮只分析并做隔离时序验证，生产确认逻辑与TTL未改。

## 独立上电

板上默认配置需覆盖控制源寄存器、帧边界生效寄存器和SC431HAI I²C初始化表。现有active增益397/256/471与load设置389/256/427不同；只改active寄存器会被控制源下一帧覆盖。现有load还依赖图像配置与sensor-restore两次主机操作，不能用它验收独立启动。

SRAM候选验证通过后再提供具体Flash器件/地址/原映像备份/启动选择/恢复步骤，由主控审核后实施。最终必须实际完成断电、拔掉电脑连接、独立供电、初始化、实时画面与新车牌识别；本阶段未下载SRAM、未写Flash。
