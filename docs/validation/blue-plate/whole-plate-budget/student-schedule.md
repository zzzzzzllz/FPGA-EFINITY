## 1. 已执行的检查

- 18 个主干 Conv/Pool，**289,032 个输出元素逐元素一致**；所有 DDR 读、行写、内部缓存、上下文高度和、logits 地址检查通过。
- 四个 context 分支在各自生产结束后立即消费、投影，再开始下一主干操作；每个分支复用同一高度和缓冲，完整 tap 不常驻片内。
- 四个整数池化分支的高度和、平方和与独立参考一致；高度和最大范围为 0…1020。分支投影和最后高度均值的 float64 重排误差 **2.8422e−14**。
- 本次 Python 进程退出码 **0**；源模型、契约和原成本 JSON 的 SHA-256 前后未变。日志在 `tmp/blue-plate-whole-plate-budget/student-schedule.log`。

这里验证的是地址、存活期和算术组织。测试用量化为右移 5 位、正向 half-up、ReLU/uint8 限幅，不是训练模型的量化参数。能量倒数和跨分支整数增益尚未实现；浮点重排正确不等于 QAT 后逐位等价。Python 保留的所有参考张量仅供比较，不计入硬件存储。

## 2. DDR 布局和存活期

使用两个独占的 64 KiB scratch 槽，以任务专属 DDR 基址 B 为起点：A=`[B,B+65536)`，B槽=`[B+65536,B+131072)`。这只是**相对布局**，没有占用现有物理地址；接入时必须由统一内存图分配，并检查与视频帧槽、权重区、其他任务无交集。

张量按 HWC 存放，行 pitch 向上对齐 16 B。每个算子读取一个槽、写另一槽；写响应全部完成后才交换槽。每次算子/分支开始都使读缓存标签失效，防止复用地址命中旧数据。单张量最大 58,144 B，因此每槽 64 KiB 足够。

| 生产阶段 | 输出形状 C×H×W | 含行对齐的 DDR 字节 | 后续消费 |
|---|---|---:|---|
| 输入 | 1×48×160 | 7,680 | stem |
| stem | 8×46×158 | 58,144 | context 2，然后 pool |
| pool 1 | 8×22×156 | 27,456 | block 1 |
| block 1 三个窄层，各自交替槽 | 4×22×156 | 13,728 | 下一层 |
| block 1 输出 | 16×22×156 | 54,912 | context 6，然后 pool |
| pool 2 / block 2、3 窄层 | 8×10×77 | 6,240 | 下一层 |
| block 2、3 输出 | 32×10×77 | 24,640 | block 3 或 context 13 + pool |
| pool 3 | 8×4×38 | 1,216 | 1×4 head |
| head 1 | 32×4×35 | 4,480 | 1×1 head |
| head 2 | 66×4×35 | 9,280 | context 22 |

每个 context 先遍历平均池化窗口，同时计算平方和与按时间/通道排列的高度和；再使用能量缩放投影，串行累加到最终 logits。其后立即释放高度和缓冲。最大高度和为 66×35×16bit，4,620 B；最终 logits 在全部分支期间保留 66×35×32bit，9,240 B。没有物化 122×4×35 拼接张量，也不同时保留四张 tap。

原模型物化输入+输出峰值 85,600 B 是 DDR 双槽容量需求的一部分，不能拿它来否定此串行片上工作区；同时，也不能省略 DDR 成本，把本调度称为全片上执行。

## 3. 12 RAM 工作区与端口

数据 RAM 是 **7 个 512×20** 并联，使用其中 128 位，构成 512×128。低 256 行作为 4 KiB direct-mapped 读缓存，高 256 行作为 4 KiB 输出行缓冲。当前最大输出行 **2,496 B**，无需额外行缓存。标签使用一个 512×16 RAM；当前 128 KiB arena 只需 5 位 tag 加 valid。

按本机 Efinity `efx_ram10.v`，RAM 是一个读端口、一个写端口，且同地址碰撞未定义。本调度采用以下顺序，主动避免碰撞：

1. 读标签；miss 时完成 DDR 16 B 填充，再写标签。
2. 读缓存数据，取一个激活值供 8 个 MAC 广播。
3. 每个最多 8 通道的结果组，对输出半区做读改写；跨 16 B 边界分两次，分别等待读数据后写回。
4. 一整行完成后，以 128 位拍读出输出半区写 DDR；等待完成再复用该行缓冲。

代码记录了跨边界输出读改写、行清零和 cache miss 数。这个顺序只要求每个 RAM 每次一个读或写动作。没有假设 byte-enable 能任意覆盖 128 位跨银行字节，也没有给 DDR 输入、卷积读取、输出写回同时分配三个端口。其余 **4 RAM 是未使用工作余量**，不能算作已经实现的统计或并行缓存。

权重常驻 16 RAM：8 路各自 8 位权重由四个 16 位银行服务，1,763 个打包 K 行按 512 深度分四组。偏置/乘数/移位可按 312×72 位组织为四个 512×20 RAM：32+32+8 位，包含移位字段。实际 QAT 若需要更宽字段，必须重算。

上下文端口修正：高度和用 512×16，ceil(2310/512)=**5 RAM**；int32 logits 用两个 512×20 宽度银行、五组深度，共 **10 RAM**，合计 **15 RAM**。原 14 RAM 只近似按字节容量相除，忽略了端口与深度分组。

| 分配 | RAM10 |
|---|---:|
| 全模型打包权重 | 16 |
| bias / multiplier / shift | 4 |
| 共享 128 位缓存/输出行 + tag | 8 |
| 工作余量 | 4 |
| 高度和 + logits | 15 |
| CTC/LUT、resize、控制原目标 | 2+1+1 |
| **新核目标** | **51** |
| 保留底座 131 + 外置灰度 14 + 新核 | **196** |
| 距原 204 上限 | **8** |

其中 47 RAM 是去掉 4 RAM 工作余量的分配总和；CTC/LUT、resize、控制仍是预算项，不是 map 结果。resize 可串行复用这组 DMA 缓冲，但需证明与灰度两行访问的时序。8 DSP MAC 可以处理 int8 激活和 int16 高度和乘 int8 权重；重量化/能量增益可复用或预留乘法器，具体 DSP 数须由冻结定点实现决定。

## 4. 流量和时间代价

本次地址轨迹与激活数值无关，固定为：

| 项目 / ROI | 数值 |
|---|---:|
| 逻辑激活/池化采样 | 1,389,772 |
| 16 B 读缓存 miss | 29,089 |
| DDR 读 | 465,424 B |
| DDR 中间特征写 | 289,632 B |
| **合计** | **755,056 B** |
| 输出读改写端口动作 | 83,596 |
| 输出行清零写拍 | 18,102 |
| 8 路卷积/分支投影 MAC 调度 | 453,362 周期 |

流量包括四个分支池化读取，不包括输入 resize 写入的 7,680 B、启动时权重和参数装载、最终结果发布。片内 CTC 可直接使用 logits，不要求再把完整 logits 写 DDR。以 10 ROI/s 为例，中间特征有效流量为约 **7.55 MB/s**；这不是 DDR 已保证的带宽。

每个采样先读 tag 再读 data，仅这两步已是 2,779,544 个串行端口动作。把 MAC、max 比较、平均池化加法、平方/归约、高度和、logits 读写、缓存填充及输出维护也各按一个串行动作计入，得到 **43.85364 ms @100 MHz** 的情景值。还未包含 DDR 等待、命令控制、平均池化除法、四次倒数、增益乘法、CTC 和 resize；这不是周期精确 RTL 仿真，也不是延迟上界。

可在后续用连续遍历、标签流水、返回数据同拍 MAC 等方式提高吞吐，但本轮不为此增加复杂缓存或第二套执行器。先确认轻量模型效果，再根据可接受的整链延迟决定是否值得优化。直接将 453,362 周期换算为 4.53362 ms 会漏掉上述存储访问。

## 5. 进入 RTL 前仍需关闭的缺口

- **整数上下文：** epsilon 到量化域的换算、池化舍入、倒数精度、分支增益统一尺度、int32 logits 累加范围。当前 15 RAM 布局要求最终存储确实为 int16/int32；若改为更宽，必须更新预算。
- **CTC/resize：** 现有 2/1 RAM 目标的真实表大小、端口与算法开销；当前脚本不验证它们。
- **XLR：** 既有底座加保留模块只在理想打包情景下剩约 5.9–6.8k XLR；本脚本没有生成新的综合证据。即使 RAM=196，仍不能认定整个系统可装入。
- **集成：** scratch 物理地址、DDR 仲裁、ready/valid、取消后排空、raw frame hold/release 与结果时效。这里的顺序完成语义必须落实到真正 AXI/自定义端口。

这份结果解决了“12 RAM 工作区是否存在可解释、可运行的调度方案”，并修正了上下文 RAM。当前模型准确率、量化与整机资源仍由各自验证门槛决定，未把地址检查通过写成硬件方案已经完成。
