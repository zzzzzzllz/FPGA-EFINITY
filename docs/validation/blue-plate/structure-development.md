# 七区可见笔画结构诊断（开发集）

复用既有全局二值/投影结构检查后，新LPRNet的56张开发集中间遮挡误接受全部被拒；代价是新增拒绝21张原本识别正确的完整图。304张开发正图由249正确/0错/55拒变为**228正确/0错/76拒**。912张开发残缺全帧与107条已见真实诊断记录均拒绝。规则已冻结，等待主控审核84张校准确认；未运行该确认或读取112张heldout。

EasyPR以局部Otsu应对光照不均，再通过行跳变、白像素比例和轮廓尺寸检查文字结构。`verifyCharSizes`的`int percPixels=area/bbArea`使其比例检查几乎不起作用；`GetChineseRect`从第二字符推算汉字范围，不能证明汉字可见。SVM判牌属于牌/非牌判断，也没有逐字完整可见保证。这些部分没有直接移作完整性放行条件。

当前项目已有`baseline.segment(roi, global/local, projection-char)`，包含实际前景区域、切分谷值和尺寸检查。直接调用其中的结构部分即可，不需要恢复旧定位器或旧字符分类器。主候选在评价前指定为全局版本；局部、二者任一通过、二者同时通过，以及EasyPR行统计均预先列为对照，没有根据失败单例增加分支。

## 冻结规则

输入仅为现有Q32/Q5采样产生的uint8 BGR 224×64。结构函数不接收号码、标签、干预掩膜、输入组别或CTC概率。

主候选`measured-seven-global-v1`：调用原`baseline.segment(roi, 'global', 'projection-char')`，只有实际返回七个区域才通过，然后与原LPR严格门限及独立颜色/边界条件相与。

- 复用77R+150G+29B右移8位灰度和原32档整数Otsu；单灰度档拒绝。
- 复用原外围清零、行跳变至少8/白像素不超过190、连通域和边框处理。
- 在原六个位置窗口内寻找实测投影谷值，谷值必须≤8；不是固定等宽切七份。
- 七区都必须有实际前景，纵向坐标跨度至少23，即包围盒高度至少24像素，宽度不超过36；原函数还对测得区域重新Otsu。没有靠推断框补齐缺字。

这是原代码的具体行为，不声称来自EasyPR的逐项原参数。局部对照复用项目已有4×2、32档Otsu；独立EasyPR行统计对照则按上游8×2、256档Otsu实现，要求16—45跳变的行占比>.40，白像素比例.15—.50，按上游循环不计最后一列。两种局部算法没有混称为同一实现。

原CTC门限固定0.9931710550839266；0.9386077887914179只作对照，不能作拒绝后的回退。基线颜色采用本次开发冻结记录的原生crop学习型蓝类和HS，raw角点/框边距均≥1。新结构条件只附加拒识，不沿用HyperOCR .9/.8。

## 正确损失与分布

主候选新增21张正确拒绝，占原249张正确接受的8.43%。其中7张谷值不合格、9张至少一区为空、4张区域过宽、1张区域过短。已查看sample13、30、69、117的原ROI与二值图：光照使前景丢失、边框与字笔画粘连或改变谷值；这些图的原LPR号码正确，损失如实计入，不标为原图缺字。

sample13和117可由局部二值版本恢复，故“任一通过”多保留2张正确图；它要额外执行局部阈值及一轮结构检查。本轮保持预先指定的全局主候选，最小方案先供审核；任一通过作为有实测收益的对照保留，不偷偷替换主选。

在原严格接受的249张正图中，全局七区最小前景高度的0/25/50/75/100百分位为0/36/38/39/45像素；56张误接受遮挡图全部为0。最小区白像素相应为0/252/313/387/744与全0。存在完整图也变成空区的重叠，不能宣称该特征能无损区分完整与遮挡。局部分布与逐区白像素、谷值、bbox均保存在`distributions.json`、`records.json`。

另构造七根高竖条，结构检查会通过；删除首根后拒绝，纯空白也拒绝。这说明规则确实要求首区像素，却不证明这些像素是合法、完整的汉字或字母。该构造只说明结构模块边界，没有将其当作整条LPR误接受。部分笔画仍在、遮挡未清空一个区、字符粘连等情况，仍需后续专门验证。
