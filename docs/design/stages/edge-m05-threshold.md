# M05：Sobel 阈值调节

状态：完整仿真、构建和SRAM板上自动检查通过；用户回复“正常”，实物按键和画面人工验收通过。完整按键响应≤100ms仍待测量。

## 操作

- 默认阈值32，判定为`G>T`，范围0～2040。
- KEY2减16，KEY3加16；到上下限后保持，不回绕。
- 按下稳定20ms后调节一次；按住500ms后，每100ms重复一次；释放不补发。
- KEY0仍是系统复位。KEY1本阶段不使用。
- 屏幕底部显示`T=0032  KEY2-  KEY3+`。数值来自当前HDMI帧携带的参数。

```bat
camera-control.cmd --edge --threshold 128 --samples 1
camera-control.cmd --edge --threshold 32 --view compare --samples 3
test-edge-m05.cmd
test-edge.cmd
build-edge.cmd
load-edge.cmd
```

`threshold_pending`是待提交阈值，`sobel_threshold`是采集帧边界锁定值，`threshold_shown`是已经进入HDMI有效像素的帧参数。`threshold_epoch`记录阈值提交次数，`key_minus_events/key_plus_events`记录按键事件。读取状态和切换视图均保留当前阈值；JTAG写入翻转提交位，因此可将按键改动后的值重新设置为先前写过的数值。JTAG与按键同周期冲突时JTAG优先，同时按两个调节键不修改阈值。

## 引脚依据

厂家软硬件手册按键表和`01_Ti60F225_key_demo/LED_8bit_Test.peri.xml`一致：KEY2为N14/GPIOR_21，KEY3为A3/GPIOL_03，3.3V、低有效。KEY0/C4/GPIOL_07保留复位。资料包中的旧原理图将KEY2画在GPIOR_24，与手册和按键例程冲突；现有摄像头工程已将GPIOR_24用作LED输出。本阶段按厂家例程接线，实物逐键对应由人工验收确认。

## 帧一致性

`threshold_control.v`在50MHz摄像头域处理按键和JTAG请求，在传感器帧边界提交。`sobel_pair.v`在输入SOF锁定阈值，并随梯度流水线传递，帧中修改不会改变本帧判定。原RGB、边界定义和梯度公式保持不变。

DDR首字的第1、2号像素使用原帧标记的空闲位携带11位阈值；第0、3号像素仍携带帧标记，后续所有像素继续带标记。RGB和二值边缘均原样保存。`compare_display.v`读到首字后输出，并将阈值放进输出帧前两个像素的高位元数据。该参数随像素通过实际HDMI FIFO，`threshold_osd.v`在有效画面开头解码，在底部状态条显示。彩色／灰度／边缘／对比四模式共用此路径。

显示参数通过带确认的快照跨回摄像头调试域；发送端保持数据直到确认。响应计数从待提交值变化开始，到实际HDMI帧读回该阈值结束，单位为50MHz周期。它包括等待帧边界、处理、DDR发布与HDMI帧选择，不包括按键的20ms消抖及显示器内部延迟。

`stored_pixels`继续在帧缓存实例前声明、在Sobel输出处显式连接。构建检查同时检查RGB的48位入口，避免非零元数据掩盖恒零RGB。

## 两分钟人工验收

1. 默认对比画面可见，底部显示T=0032；移动物体时两侧同步更新。
2. 短按KEY3十次，每次松开，数值每次加16，最终0192；短按KEY2十次回到0032。
3. 对准细纹理或弱轮廓，增大阈值应减少弱边，减小阈值应恢复更多边缘；数字与当前画面一起更新，不出现半帧不同阈值。
4. 长按KEY3约14秒到2040，继续按住不回绕；再长按KEY2约14秒到0000，继续按住保持0；短按KEY3两次回0032。
