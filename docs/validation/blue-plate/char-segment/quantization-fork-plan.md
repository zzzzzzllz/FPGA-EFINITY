## 唯一候选与顺序

tap2为 `backbone.11.block.6` 卷积及原BN/ReLU后的256×18×44张量。完整卷积仍只计算一次：

1. 对全部256通道按首候选原Q31乘数、shift、scale和zero重定标，保留原上下文支路输入，逐元素应与首候选一致。
2. 从同一含bias的int32累加值选通道0,4,…,252，共64通道，ReLU后用新的主干尺度重定标为A8。只以207train的原FP32融合ReLU端点这64通道的min/max生成尺度，不读取评价标签或利用评价结果。
3. 主干A8做原3×3空间MaxPool2d，stride=(1,2)，得到64×16×21。通道切片已完成，不能再隔4抽取。上下文仍用原256通道A8做4×10均值池及能量归一化。
4. backbone.16输入scale改为该主干scale，因此重新派生该层bias量化、zero修正和输出乘数/shift。其权重int8、权重尺度、BN状态及输出尺度不变，其后所有尺度/参数不变。tap2原bias和上下文乘数不变，仅新增64组主干乘数/shift。

BN先融合，int32含bias后进行ReLU再重定标。对实数原模型，通道选择与逐通道ReLU、空间max可交换，因为它们不混合通道；对任意固定通道，正尺度单调RNE/clip也与空间max交换。不能跨通道使用各异scale直接比较。会验证FP32显式切片→空间max与原MaxPool3d完全一致，并独立用NumPy/Fraction验证从int32分叉及两路输出。

## 现有资源内的布局

以 `whole-plate-budget/full-lprnet-sharing.md` 与 `color-cnn-sharing.md` 的51 RAM、同8 DSP、两个256KiB DDR特征槽、4KiB写块、512×72bit参数银行和8MiB arena为边界，不使用历史C8小模型的50RAM口径。

- 原tap2 A8占202,752B；新增主干A8占50,688B。放在同一输出槽的偏移0与202,752，结束253,440 <262,144B；旧输入64×18×44在另槽占50,688B。该阶段两槽存活共304,128B，没有额外特征槽。主干A8必须保留到maxpool最后一次读取，原上下文A8保留到上下文消费结束；两者未释放前不得覆盖输出槽。
- 每块12空间点，两路输出分别12×256=3,072B和12×64=768B，共3,840B，使用既有4KiB写块。两次顺序DDR写入完成后才复用，仍只有一个在途事务。tap2共792点，66块；原16点方案50块。不同时保存int32特征图，仅保留既有8 lane累加寄存器直至两路串行重定标完成。
- 参数原256条，加64条主干副本，按72bit完整行分配为320×9=2,880B，占512条银行中的320条；新增常量实际64×(multiplier32+shift8)=320B，按整行/DDR16B对齐分配576B。可将备用bias字段置0，不重复加bias。全局scale/zero是研究配置，硬件运行使用整数常量。主干下一层参数条数不变。
- 额外主干重定标50,688次，无新增卷积MAC；为守住写块尺寸，tap2权重读取由50×16,384=819,200B变成66×16,384=1,081,344B，增加262,144B。额外A8写入50,688B；maxpool改读紧凑64通道，不预支任何读流量减少收益。
- 同一8 DSP串行复用重定标，沿用int64乘积与int32累加；新增乘数必须通过原界×M<2^63检查。参数/输出存储均未扩宽，无新增RAM银行。静态常量源额外576B后总arena预留7,015,168B<8MiB。实际XLR、时序和DDR延迟仍未实现，不声称整体硬件通过。

上述仅证明本次分叉增量不扩大预算。原完整网络的整数上下文/最后投影顺序与硬件高度交换方案尚未位精确统一，本轮不批准改动它们或直接导出网络RTL。
